# 能碳标准与术语知识库

更新时间：2026-06-13

## 使用原则

本文用于沉淀能碳管理平台开发过程中必须查阅和引用的标准、政策、术语和计算口径。后续涉及能耗查询、能源强度、能效对标、能流分析、能效平衡与优化、碳核算、产品碳足迹等业务逻辑时，先查本文，再决定是否新增调研。

规则：

- 业务公式、阈值、标杆值、损耗率、节能率、能源绩效参数必须有来源。
- 来源优先级：国家标准全文公开系统/全国标准信息公共服务平台、国家发展改革委、国家市场监督管理总局、工信部、生态环境部、ISO/GHG Protocol 官方资料。
- 暂无权威来源时，只能标注为企业假设、顾问建议或示例数据，不能在产品或文档中宣称为国家/行业标准。
- 标准文本不能全文复制到仓库；本文只记录题录、适用范围、实现约束和链接。
- 产品 UI 不展示开发解释，但业务数据可展示来源、标准、有效期、置信度、适用范围等审计字段。

### 对领域模型的约束

1. `organization_boundary` 是独立领域：报告主体、报告期、组织边界、运营边界、边界设施、边界版本不能继续隐含在企业档案或区域树里。
2. `carbon_accounting` 只拥有组织排放活动记录、核算批次、核算结果和审核状态；设备、区域、产品、因子、能源事实只引用或读取。
3. 组织核算结果应以 `EmissionInventory` 或读模型输出给碳资产、核查、预算和分析页面，不允许这些页面反向修改 Scope 活动事实。
4. 行业核算方法需要配置化，至少保留行业、标准号、适用期间、排放源、活动数据单位、因子来源、报告模板和置信等级。
5. 配额履约需要读取已确认或已锁定的组织排放清单；草稿或被驳回的 Scope 记录不得进入履约缺口。
6. `organization_boundary` 首版已落表并提供 `/api/carbon/organization-boundary/*`：报告主体、报告期、边界版本、边界设施和发布状态要显式建模，后续组织排放清单、核查材料和配额履约必须引用边界版本。
7. `carbon_accounting` 首版已提供 `/api/carbon/accounting/batches*` 和 `/api/carbon/accounting/inventories*`：组织排放清单以批次快照保存，只纳入已审核记录，缺因子/缺结果必须进入质量状态，不得静默算入正式总量。
8. `carbon_verification` 首版以发改委工业其他行业报告格式、生态环境部核查指南和本地 vcarbon 行业/第三方核查样表为基础，已形成通用 DOCX 模板、`/api/carbon/verification/*` 读模型和 ZIP 导出任务；导出记录必须保留模板来源、报告范围、文件哈希、导出人和导出时间。
9. 通用模板当前定位为 `organization_ghg_generic_v2026_06_13`，文件为 `docs/评价方案/templates/工业企业温室气体排放盘查报告与核查材料包通用模板.docx`。模板字段、材料包目录和后续渲染边界见 `组织碳盘查报告与核查材料包模板设计.md`。
10. 平台生成的是企业自报盘查报告和核查支撑材料包；第三方核查报告、核查结论和核查声明必须由核查机构基于核查准则出具，不能由系统自动宣称“已核证”。

### 对领域模型的约束

1. `product_footprint` 的聚合根建议为 `ProductFootprintStudy`，而不是 `ProductionProduct`。
2. 产品主数据、产量、价格、产线关联继续由 `production_denominator` 提供；PCF 只引用这些对象作为清单输入、声明单位或分配依据。
3. 每个 PCF 研究必须显式记录 `functional_unit` 或 `declared_unit`；没有单位时不允许发布结果。
4. 生命周期阶段、活动数据清单、因子匹配、分配规则和数据质量评级必须可追溯；缺数据时返回 `incomplete_inventory`，不能补一个静态系数伪装完整 PCF。
5. 绿电、绿证、抵消或碳信用不能默认直接抵减产品碳足迹；只有采用的标准/PCR/项目规则允许并记录凭证时，才可在报告中作为单独信息展示。
6. 比较声明、碳标签和认证状态应独立建模；一个内部 PCF 计算结果不能自动升级为认证报告。

2026-06-13 首版落地状态：`product_footprint` 已按上述约束新增 PCF 研究、产品系统边界、生命周期阶段、活动数据清单、分配规则和结果版本。首版计算只对有活动量和因子、或有供应商 PCF 值的清单项生成结果；缺边界、缺活动量或缺因子时返回业务状态。当前结果定位为企业内部 PCF 计算和报告读模型，不作为 EPD、碳标签或第三方认证结果。

## 八、对当前实现的直接修正要求

### 能效对标

当前 `行业标杆库` 可以保留，但需要补强：

1. 标杆类型：内部对标、外部对标、政策标杆、设备能效等级、历史基线。
2. 来源字段：标准号/政策文件号、发布机构、实施日期、数据来源 URL、适用边界。
3. 指标体系：指标编码不能只靠通用枚举，应支持标准中的产品、设备、工序和单位产品能耗指标。
4. 生成自历史的标杆必须标注为内部标杆或历史基线，不应默认叫行业标杆。

### 能流分析

当前能流分析已经有输入、转换、分配、用能系统、区域、损耗节点，但需要修正：

1. 固定转换损耗率和分配损耗率只能作为示例估算，不能作为实测损耗。
2. 能流网络结构应对齐 GB/T 28749-2012 的购入存储、加工转换、输送分配、终端使用环节。
3. 能流图需要记录每条链路的来源：计量实测、聚合、估算、人工录入。
4. 缺少转换设备、输配网络、库存变化和终端输出计量时，应返回数据质量状态，而不是强行闭合平衡。

### 能效平衡与优化

当前首版已经补入规则测算和优化记录，后续继续完善：

1. 平衡对象：企业、园区、区域、用能系统、设备组。
2. 平衡边界：输入、输出、有效利用、损失、回收利用、库存变化。
3. 节能量方法：按 GB/T 13234-2018 区分整体法和措施法。
4. 能源基准：按 GB/T 36713-2018 记录基准期、报告期、影响因素和归一化参数。
5. 优化建议：参数优化测算必须标注方法、假设、适用设备类型和置信度；规则应沉淀在 energy 领域 policy，不应散落在 Controller 或 SQL 查询服务中。

### 用能与碳排放预算管理

当前首版按企业预算管理规则落地，未声明为国家标准或认证口径：

1. 能源执行率：`actual_tce / budget_tce * 100`。
2. 碳执行率：`actual_co2e / budget_co2e * 100`。
3. 预警阈值：执行率 `>=90%` 且 `<=100%`。
4. 超限阈值：执行率 `>100%`。
5. 预测口径：按已有实际月份运行率外推至预算周期末。
6. 实际值来源：读取 `energy_consumption_fact_v` 的 `tce_amount` 和 `co2e_amount`；无预算、无实际值、分母为 0 时返回业务状态或空值。
7. 数据追踪字段：预算方案、月度分解和调整记录应保留 `source_name`、`standard_code`、`confidence_level`，其中 `standard_code=enterprise_budget_rule` 表示企业预算管理规则。

### 碳排放管理扩展

后续开发组织、产品、供应链、配额页面前，先按本知识库补齐以下追溯字段：

1. 组织边界：首版已支持边界方法、报告主体、报告期、边界设施、版本、发布状态、排除项及理由；后续补有效期选择器、修订原因和核算批次绑定。
2. 产品足迹：功能单位/声明单位、系统边界、生命周期阶段、PCR/CFP-PCR、数据质量、分配规则、报告版本。
3. 供应链数据：供应商、产品匹配、任务状态、证据、数据来源、是否核查、有效期、质量评级。
4. 碳资产：资产类型、项目/配额来源、持仓、冻结、交易、清缴/注销、适用履约期、政策/企业规则来源。
