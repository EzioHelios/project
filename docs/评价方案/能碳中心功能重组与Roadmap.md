# 能碳中心菜单重组与页面改造 Roadmap

更新时间：2026-06-13

## 统一口径

1. 客户侧菜单回归到两条主线：`能源管理` 和 `碳排放管理`。
2. 两条主线下直接放《工业企业和园区数字化能碳管理中心建设指南》第二章的 12 个业务功能大类，确保每个一级菜单都能对表指南。
3. 每个指南一级菜单对应一个页面；页面内部用二级 Tabs 承载具体业务功能、分析视图、办理流程或材料输出。
4. 不适合客户直接操作的底层数据、模型底座和系统配置，不塞进 12 个业务菜单，按数据类型拆成其他一级菜单，例如 `企业与组织`、`业务活动台账`、`采集设备与测点`、`碳排放因子库`。
5. 每个 Tab 职责必须清晰，不能多个 Tab 进入同一页面、展示同一内容、重复承载同一业务动作。
6. 未建设好的页面统一使用建设中组件占位，明确所属指南功能、计划 Tabs、依赖数据和 TODO，方便后续识别和管理。

## 统一建设中组件

未建设完成的指南页面或 Tab 不再临时拼看板，也不跳到不相关页面。统一使用 `UnderConstructionModule`。

### 组件职责

| 字段 | 说明 |
| --- | --- |
| `guideTitle` | 对应指南业务功能名称 |
| `moduleType` | 业务办理型 / 分析展示型 / 数据台账型 / 运营处置型 |
| `plannedTabs` | 后续将建设的二级 Tabs |
| `dataDependencies` | 依赖的数据底座，例如企业档案、电表、因子库、Scope 记录 |
| `currentFoundation` | 当前已有可复用能力 |
| `nextTodos` | 后续开发 TODO |
| `status` | 建设中 / 设计中 / 等待数据 / 待开发 |

### 展示规则

1. 建设中组件只用于未完成页面或未完成 Tab。
2. 建设中组件不能伪装成已上线功能。
3. 建设中组件必须给出 TODO 和数据依赖，方便后续拆任务。
4. 已上线页面不能混入无关建设中模块，避免客户误解。

## 改造方案

### 阶段 0：路由与菜单骨架清理

目标：先把导航逻辑清理干净，不再让多个菜单指向同一个混合看板。

| 任务 | 说明 | 验收 |
| --- | --- | --- |
| 重建客户侧菜单 | 顶层保留 `能源管理`、`碳排放管理` 两条业务主线，底座能力按数据类型拆成一级菜单 | 侧边栏能直接看到 12 个指南业务功能的归属，底座数据也不会堆成一个大杂烩 |

## 页面职责检查清单

每个页面重构前必须过这张检查表。

| 检查项 | 要求 |
| --- | --- |
| 是否对应指南功能 | 页面标题、菜单和文档都能映射到 12 大类之一 |
| 页面属性是否明确 | 业务办理型、分析展示型、数据台账型、运营处置型只能选主属性 |
| Tabs 是否互斥 | 不允许多个 Tabs 展示同一数据或同一业务动作 |
| 是否有业务动作 | 分析页至少有筛选、钻取、导出、跳转修复或生成待办 |
| 是否引用底座数据 | 页面要说明数据来源，能跳到底层台账或凭证 |
| 是否有建设中占位 | 未完成能力必须显示统一占位和 TODO |

## 一期演示口径

1. 一期先上线 `能源管理` 和 `碳排放管理` 两条主线。
2. 能源管理先覆盖能耗查询、消费量与强度、能源分析、能效对标、能流分析、能效平衡、用能与碳排预算。
3. 碳排放管理先覆盖碳排放核算、碳核查支撑、产品碳足迹、供应链碳和碳资产管理首版业务闭环。
4. 产品碳足迹、供应链碳管理和碳资产管理已进入首版业务页；高级预测、认证、外部门户和正式交易仍不伪装成已上线。
5. 因子库、设备、电表、IoT 等能力属于底座，但底座也必须按类型拆成清晰一级菜单，不再统一塞进一个“基础数据与配置”菜单。
6. 能效平衡与优化首版为可追溯规则测算和优化记录，不宣称 AI 自动调参或直接设备控制。
