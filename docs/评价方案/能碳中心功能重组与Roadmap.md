# 能碳中心菜单重组与页面改造 Roadmap

更新时间：2026-06-12

## 统一口径

1. 客户侧菜单回归到两条主线：`能源管理` 和 `碳排放管理`。
2. 两条主线下直接放《工业企业和园区数字化能碳管理中心建设指南》第二章的 12 个业务功能大类，确保每个一级菜单都能对表指南。
3. 每个指南一级菜单对应一个页面；页面内部用二级 Tabs 承载具体业务功能、分析视图、办理流程或材料输出。
4. 不适合客户直接操作的底层数据、模型底座和系统配置，不塞进 12 个业务菜单，按数据类型拆成其他一级菜单，例如 `企业与组织`、`业务活动台账`、`采集设备与测点`、`碳排放因子库`。
5. 每个 Tab 职责必须清晰，不能多个 Tab 进入同一页面、展示同一内容、重复承载同一业务动作。
6. 未建设好的页面统一使用建设中组件占位，明确所属指南功能、计划 Tabs、依赖数据和 TODO，方便后续识别和管理。

## 统一建设中组件

未建设完成的指南页面或 Tab 不再临时拼看板，也不跳到不相关页面。统一使用 `UnderConstructionModule`。

### 组件职责

| 字段 | 说明 |
| --- | --- |
| `guideTitle` | 对应指南业务功能名称 |
| `moduleType` | 业务办理型 / 分析展示型 / 数据台账型 / 运营处置型 |
| `plannedTabs` | 后续将建设的二级 Tabs |
| `dataDependencies` | 依赖的数据底座，例如企业档案、电表、因子库、Scope 记录 |
| `currentFoundation` | 当前已有可复用能力 |
| `nextTodos` | 后续开发 TODO |
| `status` | 建设中 / 设计中 / 等待数据 / 待开发 |

### 展示规则

1. 建设中组件只用于未完成页面或未完成 Tab。
2. 建设中组件不能伪装成已上线功能。
3. 建设中组件必须给出 TODO 和数据依赖，方便后续拆任务。
4. 已上线页面不能混入无关建设中模块，避免客户误解。

## 改造方案

### 阶段 0：路由与菜单骨架清理

目标：先把导航逻辑清理干净，不再让多个菜单指向同一个混合看板。

| 任务 | 说明 | 验收 |
| --- | --- | --- |
| 重建客户侧菜单 | 顶层保留 `能源管理`、`碳排放管理` 两条业务主线，底座能力按数据类型拆成一级菜单 | 侧边栏能直接看到 12 个指南业务功能的归属，底座数据也不会堆成一个大杂烩 |
| 删除伪语义路由 | 如果页面内容未拆分，不让多个菜单点进同一综合页 | 点击不同指南菜单不会看到完全相同页面 |
| 新增建设中组件 | 未完成页面统一占位 | 页面能明确显示 TODO 和数据依赖 |
| 保留旧链接兼容 | 旧 `/energy-carbon/*`、`/carbon-mgmt/*` 可重定向到新路由 | 老链接不 404，但不再出现在客户主菜单 |

### 阶段 1：先做最扎实的业务页面

目标：先把碳排放核算和碳核查支撑做成真实业务系统，不先追求看板丰富。

| 优先级 | 页面 | 改造目标 | 指南功能 |
| --- | --- | --- | --- |
| P0 | 碳排放核算 | 打通 Scope 填报、核算结果、待审核、状态流转 | 碳排放核算 |
| P0 | 碳核查支撑 | 做凭证清单、追溯链路、审核日志、核查材料包、导出 | 碳核查支撑 |
| P0 | 企业与组织 / 采集设备与测点 / 碳排放因子库 | 梳理企业、区域、电表、设备、因子之间的数据关系 | 数据采集、数据架构、模型组件 |

### 阶段 2：拆能源分析页面

目标：把现在混在一起的能源综合页拆成 3 个职责清晰的页面。

| 优先级 | 页面 | 改造目标 | 指南功能 |
| --- | --- | --- | --- |
| P1 | 能耗查询 | 重点做查询、筛选、钻取、导出 | 能耗查询 |
| P1 | 能源消费量和强度计算 | 重点做消费量、折标、强度、口径 | 能源消费量和强度计算 |
| P1 | 能源消费分析与用能策略推荐 | 重点做结构、趋势、异常、建议和待办；补能源分析事实投影的定时刷新和导入后触发刷新 | 能源消费分析与用能策略推荐 |
| P1 | 能效对标 | 重点做行业标杆库、历史基线生成、设备级对标、偏差结论和规则建议；工序级先按用能系统/产线/设备编码承接 | 能效对标 |

### 阶段 3：重构专项分析页面

目标：能流和平衡可以有图，但必须具有功能性。

| 优先级 | 页面 | 改造目标 | 指南功能 |
| --- | --- | --- | --- |
| P1 | 能流分析 | 能流图、平衡表、损耗诊断、报告动作；后续补节点钻取、链路来源和真实转换/分配损耗 | 能流分析 |
| P1 | 能效平衡与优化 | 损耗定位、异常说明、优化建议、整改闭环 | 能效平衡与优化 |
| P2 | 用能与碳排放预算管理 | 目标预算、执行偏差、预测超限、调整审批 | 用能与碳排放预算管理 |

### 阶段 4：扩展高阶碳管理功能

目标：等核算和基础台账稳定后，再做高阶业务，不提前暴露客户入口。

| 优先级 | 页面 | 改造目标 | 指南功能 |
| --- | --- | --- | --- |
| P2 | 产品碳足迹核算 | 产品/BOM/工序/生命周期边界/报告 | 产品碳足迹核算 |

| P3 | 碳资产管理 | 配额、CCER、交易模拟、履约风险 | 碳资产管理 |

## 页面职责检查清单

每个页面重构前必须过这张检查表。

| 检查项 | 要求 |
| --- | --- |
| 是否对应指南功能 | 页面标题、菜单和文档都能映射到 12 大类之一 |
| 页面属性是否明确 | 业务办理型、分析展示型、数据台账型、运营处置型只能选主属性 |
| Tabs 是否互斥 | 不允许多个 Tabs 展示同一数据或同一业务动作 |
| 是否有业务动作 | 分析页至少有筛选、钻取、导出、跳转修复或生成待办 |
| 是否引用底座数据 | 页面要说明数据来源，能跳到底层台账或凭证 |
| 是否有建设中占位 | 未完成能力必须显示统一占位和 TODO |

## 一期演示口径

1. 一期先上线 `能源管理` 和 `碳排放管理` 两条主线。
2. 能源管理先覆盖能耗查询、消费量与强度、能源分析、能效对标、能流分析、能效平衡。
3. 碳排放管理先覆盖碳排放核算和碳核查支撑。
4. 预算管理、产品碳足迹、供应链碳管理、碳资产管理先作为建设中模块，不伪装成已上线。
5. 因子库、设备、电表、IoT 等能力属于底座，但底座也必须按类型拆成清晰一级菜单，不再统一塞进一个“基础数据与配置”菜单。
