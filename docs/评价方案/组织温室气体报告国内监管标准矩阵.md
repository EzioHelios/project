# 组织温室气体报告国内监管标准矩阵

## 1. 建设结论

系统必须把以下交付物分开管理，不允许用同一个“通用模板”替代：

1. **组织温室气体盘查报告**：面向企业内部管理、供应链披露及自愿核查，采用 GB/T 32150—2025 的组织核算通则，并保留 ISO 14064-1 六类和 GHG Protocol Scope 1/2/3 映射。
2. **全国碳市场行业排放报告**：仅对纳入全国碳排放权交易市场或主管部门要求补充报告的行业启用，必须按报告年度匹配生态环境部发布的行业核算指南、数据质量控制方案和核查技术规范。
3. **核查材料包**：用于内部复核或第三方核查，包含冻结的盘查报告、活动数据、参数来源、证据索引、质量问题及审计轨迹，但不等同于正式监管报表。

## 2. 现行依据

|---|---|---|---|---|

## 3. 报告路由规则

```text
报告目的 = 组织盘查
  → GB/T 32150—2025 通用组织报告
  → 同时输出 ISO 六类与 GHG Protocol Scope 映射

报告目的 = 全国碳市场
  → 按报告年度 + 行业代码选择生态环境部技术规范
  → 找不到已实现适配器时阻止正式导出
  → 不允许静默回退到通用组织报告

报告目的 = 核查材料包
  → 使用已发布盘查报告及完成的核算运行
  → 打包活动数据、参数、证据、问题和审计轨迹
```

模板版本至少记录：报告目的、管辖区、制度代码、行业代码、适用年度、标准代码、技术规范代码、生效日期、渲染器类型、数据结构版本和实现状态。

## 4. 正式导出门禁

正式组织报告必须同时满足：

- 报告主体名称和统一标识完整；
- 盘查报告已发布，核算运行已完成，边界与报告期已冻结；
- 至少存在一条纳入边界的活动数据；
- 每条活动数据均关联冻结的计算参数和来源；
- 每条活动数据均关联已复核证据；
- 不存在缺失结果、缺失因子、缺失证据或待复核记录；
- 不存在未关闭核查发现；
- 所选目的、行业和年度具备状态为 `supported` 的报告适配器。

不满足门禁时可以查看缺口，但不得生成带有“正式报告”语义的文件。

## 5. 报告最低内容

通用组织盘查报告至少包含：

- 报告主体、报告期、组织边界、运营边界、基准年和边界变化；
- 采用的核算标准、GWP 版本、Scope 2 方法及重要性判定；
- 按气体、Scope、ISO 14064-1 六类、Scope 3 十五类汇总；
- 活动数据、单位、排放因子/参数、来源、计算结果及证据索引；
- 排除项及理由、数据缺失处理、不确定性和数据质量控制；
- 编制、复核、批准、版本和日期；
- 附录中的动态活动数据表、参数表、证据清单和变更记录。

## 7. 产品边界

系统生成的是基于企业已录入、已审核数据的组织盘查报告和核查材料。全国碳市场报送仍须由企业按主管部门流程提交；系统不得在缺少行业适配器或正式审核的情况下宣称报告已经通过主管部门或第三方核查。
