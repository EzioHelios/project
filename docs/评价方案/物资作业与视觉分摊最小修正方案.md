# 物资作业与视觉分摊最小修正方案

研究日期：2026-09-20。状态：核心修正已在本地实施，验证范围及剩余事项见 `docs/audit/material-handling-cleanup-20260920.md`；未提交、未发布线上。

## 1. 目标与结论

修正当前未提交的物资作业、分摊和视觉接入实现，不新建通用事件平台、任务系统、规则引擎、审批流、对账模块或第二套物资字典。直接替换错误逻辑，前端、脚本和测试同时改用新契约，不保留旧参数别名和旧算法旁路。

唯一业务主线：

`摄像头观测 / 人工录入 -> 待确认作业 -> 已确认作业 -> 设备小时能耗分配 -> 物资/批次结果 -> PCF 明确引用`

三项关键决定：

1. 识别观测不是完整业务作业。摄像头负责证据，物资作业负责设备、物资、有效时段及业务确认。
2. 分摊用例不再写 PCF 表；PCF 负责从当前有效结果中选取输入。
3. 首版按固定设备小时计算、保留未归属电量，不将全天电量强行分完，不承诺以移动时长还原真实作业电耗。

## 3. 作业维护：一套用例，一套校验

### 3.1 输入与维护

- 创建、部分更新、确认分别使用显式请求 DTO，禁止额外字段；更新使用 `exclude_unset=True`，区别未提交与明确清空。
- 不允许前端修改 `id/team_id/source_system/source_record_id/source_payload`、计算结果或审计字段。来源由人工创建或视觉接入命令确定，不提供 `skip_validation`、`force`、`allow_legacy` 开关。
- 设备、区域、物资引用统一做同租户、启用状态、业务关系校验；名称、编码作为服务端快照，不同时让客户端随意填写 ID 和另一套名称。
- 物资复用 `ProductionProduct`；在作业表增加必要的 `material_id` 外键并保留编码/名称快照，不另建物资实体。找不到主数据就明确返回缺项，不临时造字典记录。
- 当前仅四类设备、四种作业，不扩展其他事件。设备类型为作业支持范围的显式选择，不能仅凭设备名称猜测。
- 原有 `draft/confirmed` 足够使用，不新增审批。修改已确认作业的设备、物资、数量或有效时段，返回 draft 并使受影响结果失效；仅改备注不改变状态、时长或来源。
- 未被分摊/引用的记录可删除；已引用记录拒绝硬删除。改为撤回确认再重算处理，不用级联删除结果掩盖来源消失。修改相应 FK 删除规则。

### 3.2 视觉观测归入作业

- 保留原始 `VisionObservation`，原始时段、模型、证据和配置快照不可用普通表单修改。
- 将当前“单片段直接确认整项任务”替换为“选取观测，形成/补充该任务的作业草稿”。多个观测通过已有 `operation_id` 指向同一作业，无需新建任务表或关联表。
- 同一任务只能对应同一设备、物资批次、作业类型和数量单位；发现不一致直接拒绝。第一版不自动合并跨摄像头或不同配置版本的观测。
- 草稿保存选定观测的有效时间段集合；重叠片段做时间并集，间隙不算有效作业时间。`period_start/end` 是包络，`duration_minutes` 从有效时间段派生，不能仅用包络差代替。
- 人工录入的连续作业也写同一时间段结构；人工确认或补充时段要与不可变视觉证据区分。仅有 duration 没有时段分布的旧记录不猜测小时归属。
- 有效时间段可存于现有作业 JSON 的明确业务字段中，由 DTO 校验，不新建事件明细表。记录来源和人工修订依据，不能用任意 JSON 取代结构化校验。
- 作业确认由操作员明确完成；数量只记一次。确认后新到观测只保留观测状态，不自动追加正式作业或二次计量。
- 循环演示视频的重复片段不能全部累计成一个实际任务。演示确认显式选择一轮片段，下一项业务必须使用新任务号；不自动生成随机任务号撑大统计。
- 摄像头配置的设备和物资选择复用相同主数据校验。大屏继续展示识别结果，不在大屏重做整套作业 CRUD。

## 4. 计算边界：设备小时，不是任意重叠期间

### 4.1 固定单元及数据来源

- 首版输入为明确设备、整小时起止时间、计量边界/来源、因子。所有时间包含时区，转换 UTC 后按半开区间 `[start,end)` 运算；界面按业务时区展示。
- 计算单元固定为 `(team_id, equipment_id, hour_start)`，用现有 `MaterialCarbonAllocationRun` 表承载。按日/月计算只是枚举这些单元，不新增另一份日/月有效结果。
- Run 增加设备外键、输入摘要 hash、必要修订号；唯一约束保证同一设备小时只有一份当前结果。方法、因子、所选来源是输入而非身份键，改参数不能制造两份同时有效的小时结果。
- Result 继续以 `(run_id, operation_id)` 唯一；小时明细汇总得到物资/批次结果。不再以每次随机 run 作为业务去重依据。
- 只接受既有能源域中明确归属该设备的当前小时电量。不使用区域总电量、同名设备、功率默认值或日/月电量兜底。
- 复用既有计量边界关系；单个边界含多个用能对象但没有独立设备电量时，本轮不做第二层空间分摊。
- 同设备小时有重复、重叠来源时拒绝计算；不把 MQTT 与手工电量简单相加，也不建设来源对账。调用方明确选择现有计量来源，分摊域不反写能源事实。
- 电量单位必须可靠转换到 kWh；首版明确接受 kWh/MWh，其他单位返回错误，不做模糊字符串猜测。负值、NaN、无穷值、不完整时段拒绝。

### 4.2 首版分摊假设

建议首版只开放一个有明确依据标记的方法：**小时平均用电强度下的有效时段分配**。它是企业/Demo 估算，不是实测作业电量，不是 ISO 强制算法。

对于一个完整小时：

`作业估算电量 = 小时设备电量 × 作业在该小时内的有效秒数 / 3600`

`未归属电量 = 小时设备电量 - 各作业已分配电量之和`

- 同设备不同作业的时间重叠属于业务冲突，直接拒绝该小时，不能把两个任务都算入再归一化。
- 不将剩余电量命名为“空载电量”“损耗”或“识别遗漏电量”；仅靠当前数据无法区分这些原因。
- 示例：某小时 6 kWh，A 作业 10 分钟、B 作业 20 分钟，得到 1 kWh、2 kWh，未归属 3 kWh。不能除以已知作业的 30 分钟强制得到 2 kWh、4 kWh。
- 原 `weight_duration` 本轮直接撤出可选算法及 Demo 调用，不在缺重量时降级为时长法。重量仍为作业事实，未来在证明负载与用电关系后再增加有依据的方法。
- 该建议不是保证真实功率均匀；部署现场前需验证其适用性。没有确认该估算假设时，不生成可发布结果。现场若需精确作业电耗，应另有覆盖时段的计量依据，不新增推测分支。
- 输出同时保存能源事实 ID/修订、来源质量、有效时段、方法编号与版本、参数依据。电量即使为实测，分到作业的量仍为估算；模拟来源继续标记模拟。
- Decimal 运算后按固定精度取整并把尾差留在未归属项，保证能量守恒且不超分。

### 4.3 幂等与失效

- 同输入摘要重复调用直接返回同一结果，不新增 run/result、不修改更新时间伪装新计算。
- 输入改变时，在同一小时单元事务内更新当前结果。结果行按稳定键更新；已无效但有引用的行保留失效状态，不能删除后重新分配身份。
- 锁定明确租户的设备/小时单元，依赖唯一约束处理首次并发；不是 catch 任意数据库错误后忽略。
- 不建设额外计算历史实体。用当前输入/结果快照和修订号满足本轮重复计算要求；将来真正需要历史版本时再扩展。
- 编辑作业后，显式使受影响小时及其派生清单失效。能源修订、因子变化在读取有效结果、发布、PCF 计算和导出前，通过同一新鲜度校验检查输入摘要；不能只依赖页面提示。
- 不新增异步失效总线。失效检查只处理 `material_allocation` 来源，其他 PCF 来源逻辑不重构。

## 5. 因子与 PCF：引用，而非顺手写入

### 5.1 因子选择

- 移除默认 `0.570300` 和直接浮点因子参数；必选现有可读取、启用、已确认且适用于该期间与地域的 `EmissionFactor`。
- 复用/提取因子库现有读取校验方法，不新建 factor service 副本。企业因子只读本租户，公共因子可读但不能改。
- 保存 ID、数值、单位、年份、来源/版本快照。因子年份不是有效期的同义词，地域和适用期无法确定时要求明确依据，不自动选“最新”。
- 非标准特殊系数先去企业因子库维护。本轮只支持可明确解释为电力 kgCO2e/kWh 的量纲；拒绝不明口径。数值 0 是合法值，不用 `or default` 替换。

### 5.2 引用动作归 PCF 域

- 分摊计算接口删除 `productFootprintStudyId/productFootprintStageId`，不再调用 `_publish_to_product_footprint`。
- 在 PCF 域提供“引用物资作业结果”，用户从当前有效结果选择物资、批次、期间和阶段；无需建设通用映射引擎。
- 最小版本只允许同一物资/产品主数据对应研究对象，并且结果期间在研究期间内、阶段已纳入边界。物资作为另一产品 BOM 投入时，本轮没有耗用映射，直接不开放该发布路径。
- 引用量为这一物资的分摊电量，不是整个设备电量。使用合法 `activity_type=energy`、`source_type=material_allocation`。
- 稳定来源键为设备小时单元与作业身份，目标研究内唯一。阶段不能进入去重键，移动阶段不能形成双份清单。
- 复用现有清单 `source_ref` 和专用于本来源的唯一索引；服务锁住目标研究，使用 upsert。一个当前结果本轮只绑定一个研究，避免多个研究/批次归属成为未建模的隐式分配。
- 重复引用不新增；重算后提示同步该引用，同步更新原清单而不是再添一行。来源失效的清单不得参与 PCF 新计算和新报告导出。
- 通用清单编辑不能改派生数量、因子和来源。修改回到源作业/因子；取消引用通过专用动作解除结果关联与清单，不能在通用编辑中把来源改成 manual。
- PCF 所选阶段不能同时包含同一设备小时的其他电量输入。对已结构化来源检查重叠；既有人工清单无法证明不重复时不自动发布，需明确边界并修正相应清单，不做静默扣减。
- 不再由 Demo 私自 `_refresh_product_footprint_result` 求和和改报告状态。通过正式 PCF 用例计算。
- 目前 PCF 通用计算将 total 直接填作单位足迹，未必有结构化声明数量。因此本轮的验收先到“正确的仓储电力清单输入”；若 Demo 要展示每件产品足迹，必须先明确声明数量并补该路径的数量校验，不能用另一个 Demo 算法掩盖它。

## 6. Demo 与权限

- 所有新作业、能耗、分摊单元和引用逐对象登记现有 `DemoManifest`；不新增 ownership 表。
- install 按业务稳定键更新本包对象。发现同键非本包对象报冲突，不抢占、不覆盖；用户已改动对象按保存的内容摘要检测并明确跳过/报冲突，不能覆盖后再补日志。
- 本模块 install 不执行整租户结果清理。模块清理仅处理清单中属于本包且没有外部引用的对象；现有“删除整个演示租户”作为单独明确的销毁动作，不混在 reinstall 中。
- 为四类设备准备不重叠时段和小时电量；其中视觉实测仍只有叉车，其他设备为明确模拟输入。两个租户均完整但数值不同。
- Demo 通过同一作业/计算/引用用例，不直接写最终结果。公用用例内部 flush，由最外层命令提交事务，避免 Demo 调到内部 commit 导致半包写入。
- 物资作业 read/write、计算和 PCF 引用使用现有权限体系的明确业务权限；前后端一致。识别端仅允许上报指定租户和摄像头观测，不能凭上报字段创建 confirmed 作业。
- 首版可继续用现有管理员启动本地 Demo，但不能将这种启动方式视为生产服务账号方案。不新建独立账号体系。

## 7. 代码组织与清除项

`material_allocation/schemas.py`：请求与响应；`policies.py`：时间段、守恒与纯计算；`usecases.py`：作业及小时结果事务；`queries.py`：读模型。PCF 引用用例位于现有 PCF 域，视觉只调用作业用例。无需新增 Repository 抽象、万能策略类或跨域消息总线。

直接清除：

- camelCase/snake_case 双份输入读取、无效 UTC 兼容分支。
- 部分更新中的默认值补齐、直接给 ORM 任意 setattr。
- 随机批次键代表当前有效业务结果。
- 查询期间整段归一化分摊、默认因子与缺字段降级。
- 分摊内部写 PCF、非法活动类型、Demo 自算 PCF 结果。
- 整租户 delete、模拟数据写 measured、单观测直接代表完整任务。

不重构全仓库能源录入、主数据或 PCF 架构。不新增独立“来源确认”页面。界面只在既有作业台账/详情、计算结果和 PCF 清单入口补必要操作；当前本仓库尚无物资作业前端 CRUD，实施时需要一个正式作业台账，不能将大屏按钮宣称为完整维护能力。

## 8. 实施顺序与验收

1. **作业维护与权限**：DTO、保护字段、主数据绑定、时区/有效时段、部分编辑、引用后删除限制。先补失败回归测试，再替换用例。
2. **小时分配与幂等**：稳定唯一键、明确来源、因子快照、未归属量、并发与失效。示例 6 kWh -> 1+2+3 必须守恒；跨小时截取、重复输入、重复来源、空数据和零因子均覆盖。
3. **PCF 单独引用**：重复发布、跨物资拒绝、重复能源边界、来源失效、通用编辑保护、合法 activity type。结果不可用时不产新报告。
4. **视觉归集与 Demo**：多个观测到一个草稿、时间并集、确认一次、晚到观测、重复视频；重复安装不增行、不删人工记录、不改变模拟标记。
5. **迁移、页面验证、提交**：显式冻结 DDL，补外键/唯一约束与 RLS 测试；18101 内置浏览器操作 CRUD、观测归集、计算、PCF 引用的完整结果态，再按依赖提交。

最小验收矩阵还须包含：备注编辑不变来源/单位；非法字段拒绝；同租户关系一致；跨租户与只读账号写入失败；两个并发相同计算不重复；修改计算输入后旧清单不可继续当有效结果；重量缺失不切换算法；无作业时全部电量未归属；不同任务时段重叠被拒绝；Demo 两租户均可运行。

已有 `f7/f8` 迁移已在本地应用。不得仅改旧迁移期望现库自动改变：冻结旧迁移 DDL，并以增量迁移改变约束/列。旧测试数据缺主数据或时间段时输出诊断，不在读写路径兼容；确认仅为本包模拟对象后可显式重建，其他对象保留待人工修订。没有部署证据前不操作线上数据。
