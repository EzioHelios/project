## 二、页面 Gap 分析：能耗查询

### 1. 页面定位

- 指南页面：能源管理 - 能耗查询
- 当前路由：`/_app/energy/consumption`
- 用户目标：先把查询、筛选、钻取、导出和历史追溯做扎实，不把分析、强度计算、策略建议混进本页。
- 前置口径：能源消费事实层必须按 `能碳核算能源品种与Scope归类调研.md` 区分 Scope1 燃料、Scope2 外购电力/热力/蒸汽/冷量、能源管理品类和非能源碳排活动，避免能源品种串 Scope。

### 2. 指南和评价要求拆解

| 维度 | 基础版必须具备 | 优秀版增强 |
| --- | --- | --- |
| 能源品类 | 至少支撑评价方案中的 12 类能源类型：光、风、储、充、氢、电、气、冷、热、水、空调、空压；指南还要求煤炭、焦炭、原油、汽油、煤油、柴油、燃料油、天然气、电力、热力、原料用能、甲醇、乙醇、氢、氨等 | 能源类型动态增删，新增测点或新增能源类型不需要改代码、不需要重启 |
| 查询范围 | 单项目、单设备、多设备组合查询；多园区场景下每个园区独立统计，同类能源可聚合查询 | 100 用户同时查询集团总用电量响应 <2 秒；10 年历史数据查询不崩溃 |
| 时间维度 | 实时数据、小时、日、月、年统计；历史数据追溯 | 跨 5 分钟断点后，补录数据能自动修正统计 |
| 数据质量 | 小时/日/月/年统计值与人工核算误差 <=0.1%；冷热联供要区分冷/热；气、氢等要统一转换标准单位并验证换算系数 | 异常/缺失数据注入后有容错，动态能源类型依然纳入统计 |
| 交互动作 | 查询、筛选、组合查询、导出 | 大数据量分页/性能、并发查询稳定性、能源类型配置化 |
| 权限隔离 | 园区 A 管理员不能看园区 B 实时数据 | 多园区/集团聚合与租户权限同时成立 |

### 6. 首批开发建议

P0 只做能拿基础版分的闭环：

1. 页面改为调用 `/api/energy-carbon/energy/ledger-preview`，支持账期、来源、limit、offset，并把分页展示出来。
2. 查询区新增账期/月、设备关键词或设备选择、区域/园区选择、能源品种选择。
3. 表格补充原始单位、标准单位、换算系数/依据、数据来源、最近更新时间。
4. 增加导出按钮，先支持 CSV/Excel；导出条件必须和当前查询条件一致。
5. 增加详情抽屉，展示底层记录、计算过程、审核状态和跳转底座台账。

P1 再补优秀版证据：

1. 能源类型配置化：新增能源类型或测点不改代码即可进入统计。
2. 断点补录闭环：展示缺失、估算、补录、自动修正后的差异。
3. 多园区/集团查询：园区独立统计、同类能源聚合、权限隔离验收用例。
4. 性能验收：100 并发查询和 10 年历史分页查询测试脚本及结果。

### 4. 当前不应宣称完成的事项

- 不宣称已经完成产品碳足迹。当前产品、价格、批次产量只属于强度分母域，产品碳足迹后续应独立建模。
- 不宣称产品到设备的精确能耗归因。当前只支持企业/园区级和可筛选字段，设备级分摊需要额外分摊规则和计量数据。
- 不宣称工业增加值强度。当前只实现产品产值强度，工业增加值需要财务/统计口径数据。
- 不宣称优秀版性能指标。并发、10 年历史、断点补录、分钟级误差需要专项测试证据。
