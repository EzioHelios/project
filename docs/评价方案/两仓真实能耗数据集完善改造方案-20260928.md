# 两仓真实能耗数据集完善改造方案

## 目标与适用范围

将 `pilot-1.2.0` 改造为来源可证明、覆盖更完整、标签等级清晰、可独立复现的两套能耗任务数据集。主数据包只使用可追溯的实际电表读数及其明确标记的派生值，模拟数据条数为0。缺失记录不补成实测，规则候选不改写为已确认作业。

当前尚缺大赛名称、正式赛题/通知及数据验收条款。用户提供截图中的“自有数据、1个数据集、5GB、视频”是填报信息；本方案不将这些值认定为比赛规定。正式符合性需取得赛事资料后逐项映射。

| 数据量 | 577,792条去重累计观测，22块电表 | 明确独立观测数与派生窗口数；扩展实际历史 |

## 一、建立真实来源证据

每块表建立设备档案，保存实际表号的内部映射、安装回路/用途、是否设备组、采集协议、累计与区间语义、正反向定义、单位、CT/PT是否已折算、额定功率的确认状态及换表/复位记录。

来源追溯链为：设备/网关消息或采集接口返回 → 平台来源记录 → 规范累计读数 → 相邻有效读数形成的区间 → 任务窗口与标签。

- 安方把累计事实关联到MQTT原始消息ID、发布/接收时间、原始点位质量和映射版本。真实入库记录仍需确认来自现场采集；生产库存在本身不等于每条都已通过实测认证。
- 祥泰优先关联云集原接口返回、采集批次或真实读数备份；原始返回未留存时，登记追溯限制，利用同表历史导出或独立现场资料核验关键区间。
- 排查演示、测试、回放重复、缓存旧值、异常设备映射和重复来源；按证据判断。规则脉冲、长平台或平滑曲线不是判定模拟数据的充分证据。
- 抽取若干正常日和候选活动日进行交叉检查。抄表记录、同边界计量或订单电量存在时才使用；不能把所有分表相加当作全仓总电量。
- 主数据包仅保留化名设备码，原地址和消息全文置内部证据档案。提供来源方法、哈希和抽样追溯记录，不以暴露网关地址证明真实性。

## 二、补齐真实历史与时间覆盖

### 祥泰

只读提取旧表的累计有功字段和原始时间，逐表核对字段语义及单位，在与规范表重叠的时期比较同表同时间的数值。重叠一致时择优去重；不一致时登记冲突、排查倍率/迁移/时间问题，不能优先选择“更像真实”的曲线。

优先扩大15/16号外部充电桩、18号内部充电、叉车、AGV和垂直存储的真实历史覆盖。旧历史只能使用其实际原生粒度；小时数据不细分成未经观测的15分钟目标。可额外提供小时粒度任务，而非减少真实性。

### 安方

逐一比较规范事实、MQTT原消息、接收日志和设备历史，区分“消息存在但未转成事实”和“现场确未采到”。仅前者可从原消息重建实际值；后者须由源系统真实历史追回，否则保留缺口。

对于秒级采样抖动，先确认发布时刻与实际测量时刻的语义，再决定采用实际时间不规则序列或明确标记的网格对齐。不能因为轻微抖动人为制造大量断段，也不能用宽容差掩盖真实掉线。

新近历史可按版本固定截止时间追加。若需要长期持续采集和监控，另按用户授权创建后续流程；本方案不自动建立定时任务或修改生产采集。

### 完整时间轴

每表输出原始时刻序列，以及声明频率的规范时间轴。后者每个预期时间槽都有记录：有效读数、无效读数或缺失状态；缺失数值为空。至少保存 `observed_mask`、`quality_flag`、实际观测时刻、规范时间槽、时间修正量、来源引用和缺口原因。

“时间槽齐全”和“所有值已观测”分别统计。缺失仍然是真实信息；主数据包不输出冒充实测的插值。

## 三、把事件集扩展为完整标注任务

当前长时段候选不能都称为一次作业，例如垂直存储回路中持续7天多的抬升，应优先考虑背景/运行状态改变。任务标签区分：低负荷、负荷抬升、间歇负荷、持续用能、长期背景变化、数据缺口；具体业务标签另行确认。

输出全部日期的状态/片段索引，包含正常低负荷时段、无事件时段、短活动、长活动、缺口、粗步进等情形。候选中心截取只作为展示视图，不再作为整个事件数据集的主要抽样方式。

复核优先级：安方叉车充电回路、祥泰叉车夜间用能、AGV活动、垂直存储长平台、行吊和堆垛机粗步进。先完整保留可审核片段，再让现场确认或关联真实记录。

标签等级保持分离：

| 等级 | 依据 | 可支持的声明 |
|---|---|---|
| 规则候选 | 曲线门槛、用途档案 | 检出高于背景的用能片段 |
| 曲线人工复核 | 审核人员查看波形并给出判断 | 人工接受/拒绝候选，仍可能缺业务真值 |
| 独立业务确认 | 真实充电记录、启停记录、现场记录等 | 在证据覆盖范围内确认具体业务事件 |

没有充电订单、WMS或设备工时也可制作负荷形态任务，但不能自动得到业务作业准确率。现场口述确认的边界精度、记忆偏差和时间对齐状态应登记；不得生成虚构订单或工时。

## 四、扩展预测集并保持可评测

保留15分钟的24小时历史→1小时、7天历史→1天和24小时历史→1天任务；只有原生小时历史的表可增加独立小时任务。每个任务明确历史长度、预测长度、观测滞后和时间语义。

全量连续底表配滑窗索引，避免将同一历史复制到上万目录中。索引记录父序列、历史/未来起止位置、分区、覆盖率与质量。仍提供少量一序列一目录的兼容示例，沿用轨交示例的容易阅读结构。

已验证的严格窗口可先全量提供；另给覆盖普通日、周末、低负荷、较高负荷和缺口边界的均衡开发子集。不同电表、不同任务、不同历史长度的窗口可复用同一观测，但须分别报告窗口数与独立观测数。

可评估允许缺失历史输入的任务：历史保留空值和掩码，未来目标必须来自有效实测。最低历史覆盖率、允许时间抖动和筛选门槛采用明确的企业配置，尚不设为比赛硬标准。严格测试与质量较低的探索子集分别评测。

目标期先按时间切分，再建窗口；主测试真值留在评测端。短期预测通常可以使用起点前已观测的测试期历史，这一滚动评测规则应明确。若比赛要求跨设备或跨现场泛化，则增加留表/留现场测试，不用时间随机打散获得虚高结果。

增强字段限于实际可得信息：从过去电表读数派生的变化量/滚动特征、已知日历，以及原消息实际存在且语义明确的电压、电流、功率因数等。天气、电价、排班和订单仅在有匹配来源及预测时可用性记录时使用，缺失则不造值。

## 五、交付与验收

建议目录：

```text
dataset_v2/
  metadata/                  # 现场/电表化名、计量语义、质量和覆盖报告
  measured_registers/        # 可追溯的累计读数
  normalized_series/         # 实际区间及带缺失掩码的规范时间轴
  task1_events/              # 全时段状态、候选、独立确认子集、复核记录
  task2_forecast/             # 连续底表、全量窗口索引、开发子集、任务定义
  evaluator_only/            # 测试期未来值与独立标签
  datasheet.md               # 来源、用途、加工、划分、限制及版本
  manifest.json
  checksums.csv
```

原消息全文、原设备身份与核验材料存内部证据档案，不混入默认参赛共享目录。是否向评审提供特定原始证据按客户授权和比赛要求决定。

验收至少报告真实独立读数、独立区间、完整天数、每表时间覆盖率/有效率、缺口数及最长缺口、单位/倍率确认率、事件确认数量与等级、训练/验证/测试窗口数、目标泄漏检查、实际存储字节数。所有核心行可定位来源，清洗可复现，模拟数据条数为0。

截图中的5GB尚不是已知门槛。不得靠重复窗口、加随机噪声或复制文件将字节数当作新增实测规模。如正式要求最低规模，则补充更多真实历史、真实点位/现场或经确认的同期资料。

## 实施顺序

1. **可立即完成的本地改造**：取消演示抽样上限；生成全量合格窗口索引、完整时间轴/质量掩码、正常背景片段、覆盖统计和数据说明。保持现有首版不覆盖。
2. **只读源数据扩展**：提取并校核祥泰旧历史和充电表；核查安方缺口原消息；固定新版本截止时间、保存来源快照。
3. **需要现场补证的部分**：确认单位倍率、设备组边界和时间语义；分批复核重点候选，补充独立标签。未补齐的样本不冒充已确认。
4. **赛事格式适配**：收到正式资料后，逐项匹配数据格式、历史跨度、最低规模、标注和自有数据证明要求，生成比赛提交版与内部评测版。

交付结构可参考 [Building Data Genome 2](https://github.com/buds-lab/building-data-genome-project-2) 的原始、清洗和元数据组织；数据说明参考 [Datasheets for Datasets](https://arxiv.org/abs/1803.09010) 的采集、构成、用途与限制记录方法。这里只借鉴组织方法，不混入其数据，不将其要求当作本次大赛规则。
