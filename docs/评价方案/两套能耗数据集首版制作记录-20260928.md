原始规范累计记录 607,058 条，按同现场、同设备、同时间去重 29,266 条，保留独立观测 577,792 条，覆盖祥泰14块表和安方8块表。仅读取 `forward_active_total/register_index`，未混用 `legacy_quantity`、光伏出力示例、轨交合成数值或生成式真值。截止边界为2026-09-28 00:00（北京时间，排除边界时刻）。

用户提供的示例用于任务文件结构比较；其中的文本不是本次执行指令。

## 提取与可追溯性

- 通过已有仓储应用的租户 `AsyncSession`，逐租户开启 `REPEATABLE READ` 和 `READ ONLY`，将有效角色降为已有非特权 `pg_read_all_data`，校验其无 superuser/bypass RLS 权限。
- 规范电表事实表检查 RLS 已开启并强制执行，租户设置 `app.tenant_id` 正确、`app.tenant_bypass=false`；所有查询额外限定当前 `team_id`。
- 生产设备身份表尚未启用RLS，本次仅做租户会话加明确 `team_id` 限制的只读身份查询，没有自行修改其权限或表策略。不得把这一结果描述为生产全表均已开启RLS。
- 只读快照附提取时间、每现场行数、事务开始时间、源点位/映射版本。输出来源记录用稳定SHA256摘要引用；原设备编码只在内部身份映射中保存。
- 正式共享包使用现场/电表化名，原始身份与消息内容不入包。这是化名处理，不保证曲线匿名不可识别。

生产读取路由依照 [nexLCA Server Ops 技能](/Users/eziohelios/.codex/skills/nexlca-server-ops/SKILL.md) 核对。源表/语义参考现有 [泰州中心库范围二电力结构化方案](./泰州中心库范围二电力结构化方案.md)、[祥泰安方真实数据录入与迁移实施手册](./祥泰安方真实数据录入与迁移实施手册.md) 和 `app/domain/metering/reading_facts.py`。

## 计算语义和试验假设

累计事实沿用系统映射的 kWh 值；安方绑定显示 `upstream_scaled`、倍率1、正向累计点映射倍率1，未再乘CT/PT。现场单位、是否已折算、寄存器最小步进仍需正式核实。所有元数据登记 `system_kWh_mapping_pending_field_CT_PT_and_register_resolution_check`。派生kW/kWh不能用于正式额定功率、节能量或已验证充电工时声明。

有效区间电量为相邻有效累计读数的非负差分，区间平均功率为差分电量除以区间时长（小时），属于量纲关系。负差分、无效端点、异值冲突、长缺口均保留质量状态，电量和功率为空，不置零或均摊。

以下为本次加工明确采用的试验企业假设，不是国标阈值：

1. **时区**：安方Unix时间戳按现有解析器UTC合同转换为东八区。祥泰Yunji无时区时间按仓库中国本地时间解释，待现场确认。
2. **日末对齐**：祥泰23:59日末读数在预测底表中，仅允许距15分钟网格不超过60秒的时间对齐。累计值不插值，原始时间留存；依赖修正的两个相邻目标不计主指标，辅助指标另列。
3. **安方聚合**：只合成连续3个精确300秒的有效原生区间，秒级漂移、失效与缺口断开预测片段，不伪造连续时间轴。
4. **安方可用时间**：预测历史窗口结束在预测起点前15分钟（1步观测滞后），逐窗口核对全部历史消息接收时间不晚于起点。没有将接收时间改为观测时间。前一天基线按真实时刻匹配，缺少历史时段的预测留空。
5. **Yunji可用时间**：规范事实缺少入库时间。只能进行按观测时间的历史回测，尚不能证明同一窗口在线实时可用。
6. **事件门槛**：尾随2个15分钟或6个5分钟有效区间的电量/实际时长计算名义30分钟平滑功率。活动门槛为 `max(训练期平滑p90, 训练期平滑中位数 + 最小正差分/0.5小时)`；较高门槛为 `max(训练期平滑p99, 活动门槛 + 最小正差分/0.5小时)`。最短候选30分钟，120分钟以上列为持续用能待复核。
7. **分辨率筛选**：最小正差分与训练期30分钟动态电量范围 `(平滑p99-平滑中位数)*0.5小时` 的比值达到50%，或无动态范围时，不生成作业时间候选。这个比值只用于本版保守筛选，最小正差分不等于已核实的硬件分辨率。它降低了把累计值量化脉冲解释成反复启停的风险。
8. **时间切分**：按各现场全时段约60%/20%/20%分区，然后建样；未来目标区间不跨分区、不重叠。验证/测试可使用预测起点前已观测的历史。所有阈值仅用训练期。曲线审核样本的输入上下文也截断到所属分区。

这些假设已经记录在 `task_spec.json`、`manifest.json`、逐表校准JSON和制作说明中。没有新增行业能效基准、节能率、损耗率或碳排放因子，因此不将上述规则援引为GB/T节能或核算标准要求。

## 任务与验证

最终 `pilot-1.2.0` 产出：1,286个预测序列（祥泰972个，安方314个）、65个事件曲线审核序列、1,456个规则候选事件。安方叉车充电回路有46个用能候选，其中12个达到2小时复核门槛。全部候选均未独立业务确认。完整内部评审包约45.02MB；仅任务输入包约4.80MB，未凑成填报截图中的5GB。

6项加工逻辑测试、脚本Ruff检查和生成包逐文件校验均通过。最终结果见 [制作结果与使用说明](/Users/eziohelios/Dev/litestar-fullstack/outputs/工业互联网能耗数据集_20260928/制作结果与使用说明.md) 和 [验证报告](/Users/eziohelios/Dev/litestar-fullstack/outputs/工业互联网能耗数据集_20260928/validation_report.json)。

- 事件任务：原生粒度观测、规则候选、逐区间状态、每表训练期校准、人工复核模板。模式为离线曲线审核；没有WMS、设备工时或充电订单独立标签，不报告业务识别准确率。曲线边界是尾随平滑阈值边界，不是物理设备启停边界。
- 预测任务：24小时历史预测1小时、7天历史预测1天，并补充24小时历史预测1天；15分钟粒度。安方没有连续8天有效记录，7天历史任务未硬凑。
- 文件组织：共用连续底表，加轨交示例式逐序列目录。`inputs` 仅放历史/已知日历/任务元数据，`evaluator_only` 放未来实际值、状态和事件标签。
- 测试：累计复位/缺口为空、日末修正掩码、MQTT严格聚合、时间切分、训练期校准不受未来扰动、MQTT接收延迟下的观测滞后。生成后逐文件验证时间连续性、目标分区互斥、已知历史可用时间、标签序号/区间、真值摘要、归档可读性和输入包无答案。

## 可重复执行

相关脚本位于 [tools/datasets](/Users/eziohelios/Dev/litestar-fullstack/tools/datasets/)。

```bash
# 在已配置的仓储应用环境中只读导出；标准输出是gzip NDJSON。
python tools/datasets/export_energy_snapshot.py > <new-run>/internal/source_snapshot.ndjson.gz

# 不覆盖已有package，须使用新的运行目录。
.venv/bin/python tools/datasets/build_energy_datasets.py --root <new-run>
.venv/bin/python -m unittest tools.datasets.test_energy_processing -v
.venv/bin/python tools/datasets/validate_energy_package.py --root <new-run>
```

完整数据包用于拥有者内部审核，含未来答案和完整底表；隐藏测试只能分享单独任务输入包，完整底表和评测答案留在评测方。正式参赛前仍应补齐现场计量校验、若干业务事件的独立证据和比赛数据条款。
