# 四租户 12 页面录入完整性整改清单

更新时间：2026-06-14

## 结论

四个企业租户已经完成页面可用性、非破坏性操作、写入型流程、证据包导出和页面下载验证。但从“真实企业主要数据能否完整录入”的口径看，不能只按 `write_flow_passed=32/48` 认定完成。

当前页面写入/导入流畅度分为六类：

| 类型 | 数量 | 结论 |
| --- | ---: | --- |
| 已完成写入闭环 | 32 | 页面/API 可创建或更新关键业务对象，并完成该页面关键业务闭环 |
| 真实资料包完整导入覆盖，但页面无直接录入入口 | 12 | 可验收数据展示和分析，企业端主要通过统一导入入口或资料包导入驱动页面 |
| 真实资料包部分导入覆盖，页面无直接录入入口 | 4 | 可看见部分数据，不能认定完整录入 |
| 真实源数据缺失，页面不可做端到端录入验证 | 0 | 当前四租户 12 页面均已有页面可用或部分来源证据 |
| 真实源数据缺失导致业务阻塞 | 0 | 迈柏已通过电力来源解除空清单阻塞 |
| 缺少可验证计算结果导致业务阻塞 | 0 | 当前四租户运行结果已无缺计算结果阻塞 |

另外有 13 个组合不能计入真实企业数据完整闭环：9 个是部分来源，4 个是四租户碳资产纯模拟写入。

验证组织口径：

- 每个企业资料包必须作为 `enterprises/<enterprise_code>/` 下的独立子文件夹和独立租户处理。
- 每类数据只能进入对应页面或对应底层台账：组织碳核算来源进入 `01_carbon_accounting`，产品碳足迹进入 `02_carbon_product_footprint`，供应链进入 `03_carbon_supply_chain`，辅助核查和证据进入 `04_carbon_verification`，能源数据进入 `05_energy_management`，碳资产进入 `06_carbon_assets`。
- 总清单按“企业/租户/页面/数据类型”分别统计完整度、流畅度和阻塞原因，不跨企业借用数据，也不把演示写入计为真实企业数据闭环。

建议实现：

- 在能源消费或统一数据台账入口继续完善企业可操作的导入向导；当前已支持固定标准化包选择和单数据集 CSV 导入，后续需支持企业自行上传资料包。
- 导入对象至少覆盖 `energy_interval_facts`、`scope1_stationary_combustion`、`scope2_electricity_bills`、`production_output_facts`。
- 导入结果必须写入来源字段：`source_name`、`standard_code`、`confidence_level`、`source_file_path` 或等价审计字段。
- UI 需要显示每批导入的文件名、行数、成功/失败行、来源状态和可追溯附件。
- 日常企业用户导入不应要求 CLI 或开发人员协助；当前实施/验收整包入口仍需超级用户权限，普通企业上传式整包导入待产品化。

验收标准：

- 企业用户在页面上传标准模板后，能源消费/能源强度/能源分析/能流图能看到新数据。
- 错误行可下载，成功行可追溯原始文件。
- 不同租户导入数据隔离，不能跨企业可见。

剩余验收：

- 如果企业需要保留原始附件文件本体，需要接入对象存储或证据包归档表；当前 CSV 行可保存附件路径文本，但不上传附件文件。
- 当前浏览器级整包验证只执行固定标准化包 dry-run，不等同于普通企业用户上传 ZIP/目录包的产品化验收。
