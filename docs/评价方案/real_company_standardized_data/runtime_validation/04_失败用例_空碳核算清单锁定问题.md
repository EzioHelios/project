# 失败用例：空清单或缺结果清单曾可锁定

发现时间：2026-06-14

测试租户：`nb-maibo-2025`

模块：碳排放核算

路由：`/carbon/accounting`

## 问题概述

迈柏资料包缺少可纳入组织碳核算的已审核 Scope 活动数据。写入验收创建核算批次并重建清单后，`record_count=0`、`included_record_count=0`。修复前平台仍可能把空清单状态置为 `ready` 并允许锁定。

后续四租户重建验证又暴露出同类风险：本田曾可重建纳入记录，但其中部分记录缺少可验证 CO2e 计算结果。缺结果清单同样不能锁定，否则会把半成品核算批次误报为已完成。该风险已通过固废因子导入和缺结果锁定防线解决，当前只剩迈柏空清单阻断。

## 复现步骤

1. 切换到 `nb-maibo-2025` 租户。
2. 补齐组织边界发布前置条件。
3. 进入 `/carbon/accounting`。
4. 创建核算批次。
5. 执行重建清单。
6. 尝试锁定批次。

## 期望行为

空清单不能锁定。平台应提示核算批次尚未生成清单，并要求企业先导入或审核可纳入组织碳核算的 Scope 活动数据。

已纳入记录中存在缺失计算结果时也不能锁定。平台应提示核算批次存在缺失计算结果，并要求补齐可追溯的因子匹配或计算快照。

## 实际行为

修复前，状态策略只看 `missing_result_count`。当空清单的缺失结果数为 0 时，会被误判为 `ready`。锁定用例也未对 `missing_result_count > 0` 再做一次服务层防线。

## 根因分析

| 层面 | 判断 | 说明 |
| --- | --- | --- |
| 后端 | 是 | `inventory_status()` 缺少 `included_record_count <= 0` 的判定 |
| 前端 | 否 | 前端只是调用后端锁定接口 |

## 修复结果

已调整：

- `src/py/app/domain/carbon_accounting/domain/policies.py`
- `src/py/app/domain/carbon_accounting/usecases/inventory.py`
- `src/py/tests/unit/domain/carbon_accounting/test_inventory_policies.py`

修复后规则：

- `included_record_count <= 0` 时，清单状态为 `empty`。
- `lock_batch()` 增加防线：`included_record_count <= 0` 拒绝锁定，返回“核算批次尚未生成清单”。
- `lock_batch()` 增加缺结果防线：`missing_result_count > 0` 拒绝锁定，返回“核算批次存在缺失计算结果”。

## 验证结果

复跑四租户清单重建验收：

```text
fs-honda-metal-2025,inventory_rebuild_ready,inventory=ready,records=88,included=88,missing=0,lock_succeeded
xm-hongtong-2025,inventory_rebuild_ready,inventory=ready,records=16,included=16,missing=0,lock_succeeded
sh-malu-youjie-2025,inventory_rebuild_ready,inventory=ready,records=4,included=4,missing=0,lock_succeeded
nb-maibo-2025,source_missing_empty_inventory,inventory=empty,records=0,included=0,missing=0,lock_rejected
```

结论：平台现在正确阻断空清单和缺结果清单锁定。该页面在迈柏租户下不是平台流程失败，而是企业资料包缺少组织碳核算活动数据；本田租户下天然气 `m3` 已通过现有 `natural_gas/m³` 因子计算，3 条固废 `t` 已通过企业碳排放清册废料因子补齐并可锁定。
