## [FC-001] 碳核算 - 清单接口把 ASGI scope 当成业务范围参数

### 问题概述

访问 `/carbon/accounting` 时，`/api/carbon/accounting/inventories` 曾返回 500。

### 操作步骤

1. 登录平台。
2. 切换到 `fs-honda-metal-2025` 租户。
3. 进入 `/carbon/accounting`。
4. 切换碳核算页面多个 Tab。

### 期望行为

碳核算清单接口返回当前租户的清单数据，不应出现 5xx。

### 实际行为

接口把 Litestar 的 ASGI `scope` 字典注入到了业务查询字段 `scope`，SQL 参数中出现 `dict`，PostgreSQL 驱动报 `cannot adapt type 'dict'`。

### 根因分析

| 层面 | 判断 | 说明 |
| --- | --- | --- |
| 前端 | 否 | 页面请求本身可触发问题，但不是前端参数错误。 |
| 后端 | 是 | 控制器参数名 `scope` 与框架注入名冲突。 |

### 修复状态

已修复：

- 将接口入参改为 `scope_filter`，保留 query alias `scope`。
- 核算明细查询在存在租户上下文时显式按 `team_id` 过滤，并绕开重复租户注入。

复测结果：本田深测第二轮 `/carbon/accounting` API 失败数为 0。

## [FC-002] 辅助核查 - 历史附件状态 `approved` 导致附件接口 500

### 问题概述

访问 `/carbon/verification` 时，`/api/carbon/verification/attachments` 曾出现一次 500。

### 操作步骤

1. 登录平台。
2. 切换到 `fs-honda-metal-2025` 租户。
3. 进入 `/carbon/verification`。
4. 依次切换核查项目、凭证清单、核查材料包、报告导出等 Tab。

### 期望行为

附件接口即使遇到历史数据状态，也应返回可读列表和汇总，不应使页面崩溃。

### 实际行为

默认租户历史 MVP 附件曾写入 `status=approved`，而附件领域规则只允许 `pending_upload/ready/archived/rejected`，读取汇总时触发 `不支持的核查附件状态: approved`。

### 根因分析

| 层面 | 判断 | 说明 |
| --- | --- | --- |
| 前端 | 否 | 页面只是触发附件查询。 |
| 后端 | 是 | 历史种子数据状态值与当前附件枚举不一致，读取侧缺少兼容。 |

### 修复状态

已修复：

- MVP 种子数据后续改写合法附件状态 `ready`。
- 附件读取侧兼容历史 `approved`，并按有文件路径时映射为材料已就绪。

复测结果：本田深测第二轮 `/carbon/verification` API 失败数为 0。
