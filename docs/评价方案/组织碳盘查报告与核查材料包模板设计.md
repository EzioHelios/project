### 1.3 模板抽取结论

本地行业模板和公开通用指南的共同骨架是“报告声明、报告主体基本情况、边界和排放源识别、排放汇总、活动水平、排放因子/计算参数、数据质量和附表”。行业差异主要体现在排放源明细、活动数据字段和监管附表，因此通用模板只保留可扩展的排放源识别矩阵和可选过程排放附表。第三方核查报告样例中的文件评审、现场核查、不符合项和结论不作为平台自动出具的核查结论，而是进入核查支撑材料包、工作底稿和整改闭环。

## 2. 通用模板定位

该模板用于平台完成一次组织碳盘查，不是某个行业的法定填报模板。

适用场景：

- 企业内部组织碳盘查。
- 非特定行业或尚未配置行业专用模板的工业企业基础排放报告。
- 第三方核查前的材料包准备、工作底稿和问题清单导出。
- 评价方案中“基础碳排放报告、凭证追溯、材料包导出”的验收。

不适用场景：

- 发电、水泥、钢铁、电解铝等已有监管专用模板的正式报送。
- 第三方核查机构正式出具的核查报告。
- 产品碳足迹、供应链披露、碳资产履约报告。

## 3. 完整盘查闭环

通用模板服务的是“完成一次组织碳盘查”，不是单独导出一张表。系统实现应把以下步骤作为正式导出的前置门槛和验收口径：

| 步骤 | 业务动作 | 系统产物 | 阻塞条件 |
| --- | --- | --- | --- |
| 1 | 建立报告主体、报告期和组织边界 | 已发布 `OrganizationBoundary` 版本 | 无报告主体、无报告期、边界未发布 |
| 2 | 采集活动数据并绑定凭证 | Scope 活动记录、能源事实引用、供应链审核数据、证据清单 | 活动量缺失、单位不匹配、关键凭证缺失 |
| 3 | 选择核算方法和排放因子 | 因子参数快照、标准来源、适用期间 | 缺因子、因子不适用、标准版本未知 |
| 4 | 执行组织排放核算 | `GhgCalculationRun`、`GhgCalculationResult` 和参数快照 | 没有已审核活动记录、缺计算参数或核算运行未完成 |
| 5 | 内部复核并发布盘查报告 | 已发布、版本化的 `GhgInventoryReport` | 报告为空、质量问题未处理或审批发布未完成 |
| 6 | 创建核查项目并刷新就绪状态 | `CarbonVerificationProject`、就绪摘要 | 项目未绑定已发布报告、核算运行或报告模板 |
| 7 | 导出 DOCX/PDF 和材料包 ZIP | `CarbonVerificationExportJob`、`CarbonVerificationExportFile`、`manifest.json` | 模板不存在、未知变量、文件转换失败或附件无法读取 |
| 8 | 跟踪核查发现和整改 | `VerificationFinding`、整改证据、关闭记录 | 发现未整改或复核未通过 |

正式报告和核查材料只读取 `GhgInventoryReport` 所冻结的 `GhgCalculationRun`。旧 `CarbonAccountingBatch`、旧 Scope 台账和路径型附件不再作为正式核查接口的回退来源；迁移后未能绑定已发布报告的旧核查项目归档处理。

## 4. 报告章节

| 章节 | 系统来源 | 完成盘查的业务含义 |
| --- | --- | --- |
| 报告声明 | 报告主体、报告年度、标准来源、生成日期 | 明确报告责任主体和版本。 |
| 报告主体基本情况 | `master_data`、`organization_boundary` | 锁定企业抬头，避免企业档案变更影响历史报告。 |
| 核算边界与排放源识别 | `organization_boundary`、`carbon_accounting` | 确定报告主体、报告期、组织边界、边界设施、纳入/排除排放源。 |
| 温室气体排放量化结果 | `GhgCalculationRun`、`GhgCalculationResult` | 输出按 Scope、ISO 类别、排放源和气体汇总的冻结核算结果。 |
| 活动水平数据及来源说明 | `GhgActivityRecord`、区域设备归集、能源事实引用 | 记录活动量、单位、期间、来源、监测频次和证据。 |
| 排放因子与计算参数说明 | `GhgParameterAssignment`、因子库和运行快照 | 记录因子、参数、标准来源、适用期和选择规则。 |
| 数据质量控制与文件存档 | 审核日志、质量问题、计量与校准附件 | 说明监测计划、缺失处理、内部复核、版本锁定。 |
| 附表 A-F | 业务数据附表 | 承载主体、活动数据、燃料、电热、过程排放、因子参数。 |
| 附表 G-J | 核查支撑附表 | 承载材料包目录、文件评审底稿、现场核查清单、不符合项整改。 |
| 附表 K-N | 系统实现附表 | 承载领域映射、模板字段、ZIP 文件树和后续实现拆分。 |

## 5. 导出上下文

正式导出只读取已发布盘查报告所绑定的冻结核算运行，当前实现链路为：

```text
organization_boundary
  -> ghg_activity_record / ghg_parameter_assignment / ghg_evidence_link
  -> ghg_calculation_run / ghg_calculation_result
  -> ghg_inventory_report (published)
  -> carbon_verification_project
  -> carbon_verification.report_context
  -> carbon_verification.ReportDocumentRenderer
  -> carbon_verification.MaterialPackageAssembler
```

关键字段：

| 字段 | 来源 | 缺失处理 |
| --- | --- | --- |
| `enterprise.name`、`enterprise.unify_code` | `EnterpriseInfo` | 缺失时阻塞正式导出。 |
| `reporting_period.year`、`period_start`、`period_end` | `ReportingPeriod` 或查询筛选 | 无报告期时只能导出草稿。 |
| `boundary_version`、`included_facilities`、`excluded_sources` | `OrganizationBoundary`、`BoundaryFacility` | 无已发布边界时阻塞正式导出。 |
| `inventory.scope_summary`、`inventory.source_summary` | `GhgCalculationResult` | 无完成核算结果时阻塞核查项目。 |
| `activity_data[]` | `GhgActivityRecord` | 缺活动数据进入 `blocked`。 |
| `factor_parameters[]` | `GhgParameterAssignment` | 缺参数进入 `missing_factor`。 |
| `evidence_manifest.items[]` | `GhgEvidenceFile`、`GhgEvidenceLink` | 缺凭证进入 `missing_evidence`；未批准凭证进入 `pending_review`。 |
| `quality_issues[]` | `carbon_verification.issues` | 可随核查材料包导出；存在未解决问题时阻止正式盘查报告。 |
| `audit_trail.items[]` | 报告审批、证据复核和核查发现状态记录 | 无审核轨迹时材料包状态为待完善。 |

渲染约束：

- 报告上下文使用 `msgspec` 强类型就绪检查结构，并保留现有字典型 API 的序列化边界。
- `ReportDocumentRenderer` 使用 `python-docx` 动态创建活动数据、参数、证据和汇总表，不再通过 XML 字符串替换处理占位符。
- 正式报告固定为 A4，采用正式文档标题层级、重复表头、禁止表格行跨页拆分以及中文业务状态。
- 通用组织报告与全国碳市场行业报告分别路由；行业适配器未完成时不得回退为通用报告。

## 7. 后续实现拆分

| 对象/服务 | 所属上下文 | 职责 | 验收口径 |
| --- | --- | --- | --- |
| `VerificationProject` | `carbon_verification` | 管理一次组织碳核查项目的范围、保证等级、重要性水平、现场核查、结论、报告/运行引用和就绪摘要。 | 已绑定已发布 `GhgInventoryReport`，只有材料就绪且结论批准后才能完成。 |
| `ReportTemplateVersion` | `carbon_verification` | 管理模板名称、版本、标准来源、适用行业、文件路径和启停状态。 | 已实现首版，报告上下文和材料包读取启用模板，页面可登记默认模板、设默认和启停模板版本。 |
| `ReportDocumentRenderer` | `carbon_verification.usecases` | 读取冻结的 `report_context`，动态生成 A4 DOCX，转换 PDF 并计算文件哈希。 | 已实现动态表格和正式版式；正式报告缺失关键字段时由门禁阻止，不以业务空值冒充完整报告。 |
| `GhgEvidenceFile` / `GhgEvidenceLink` | `ghg_inventory` | 管理实际文件、内容哈希、活动数据关联和复核状态。 | 已实现真实上传、下载、哈希完整性校验和批准/驳回；正式核查不再使用路径型旧附件。 |
| `VerificationFinding` | `carbon_verification` | 承载文件评审、现场核查、不符合项、整改和关闭状态。 | 已实现首版，自动问题可升级为可关闭的核查发现。 |
| `MaterialPackageAssembler` | `carbon_verification.usecases` | 汇集报告、数据表、附件、问题和审核轨迹，写入导出清单。 | 导出任务可重试、可下载、可校验；本地附件原件会写入 `evidence/{year}/`，不可入包原因写入 manifest。 |
| `CanonicalVerificationQueryService` | `carbon_verification.queries` | 只从已发布报告、冻结运行、标准参数和规范证据生成核查读模型。 | 正式导出不允许旧清单或旧 Scope 台账回退。 |

## 8. 开发顺序

1. 已接入 DOCX 渲染 usecase：填充通用模板占位符，输出临时 DOCX。
2. 已使用 LibreOffice headless 把 DOCX 转为 PDF；运行环境没有转换器时保留 DOCX 导出。
3. 已将 DOCX/PDF 写入 `CarbonVerificationExportFile`，并记录文件大小、哈希和来源。
4. 已增加模板版本和国内监管规范目录，当前通用模板为 `organization_ghg_generic` / `v2026.07.01`，依据 GB/T 32150—2025。
5. 已新增 `VerificationProject`，支持项目状态流转、就绪摘要和附件/发现/导出任务归集。
6. 已将当前自动问题升级为 `VerificationFinding`，支持整改、复核、关闭。
7. 已新增 `VerificationAttachment` 元数据台账；本地可访问附件原件已加入 `evidence/{year}/`。
8. 2026-08-23 已将正式导出唯一事实链切换为 `GhgInventoryReport -> GhgCalculationRun/Result`，并归档无法绑定报告的旧核查项目。
9. 2026-08-23 已替换 XML 字符串渲染器，正式报告动态输出 Scope、气体、ISO 六类、Scope 2 方法、Scope 3 十五类、活动数据、参数、证据及签批页，并完成逐页渲染检查。
