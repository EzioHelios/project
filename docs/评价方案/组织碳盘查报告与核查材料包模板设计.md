## 2. 通用模板定位

该模板用于平台完成一次组织碳盘查，不是某个行业的法定填报模板。

适用场景：

- 企业内部组织碳盘查。
- 非特定行业或尚未配置行业专用模板的工业企业基础排放报告。
- 第三方核查前的材料包准备、工作底稿和问题清单导出。
- 评价方案中“基础碳排放报告、凭证追溯、材料包导出”的验收。

不适用场景：

- 发电、水泥、钢铁、电解铝等已有监管专用模板的正式报送。
- 第三方核查机构正式出具的核查报告。
- 产品碳足迹、供应链披露、碳资产履约报告。

## 3. 报告章节

| 章节 | 系统来源 | 完成盘查的业务含义 |
| --- | --- | --- |
| 报告声明 | 报告主体、报告年度、标准来源、生成日期 | 明确报告责任主体和版本。 |
| 报告主体基本情况 | `master_data`、`organization_boundary` | 锁定企业抬头，避免企业档案变更影响历史报告。 |
| 核算边界与排放源识别 | `organization_boundary`、`carbon_accounting` | 确定报告主体、报告期、组织边界、边界设施、纳入/排除排放源。 |
| 温室气体排放量化结果 | `CarbonAccountingBatch`、`CarbonEmissionInventoryItem` | 输出按 Scope、排放源、气体和质量状态汇总的组织排放清单。 |
| 活动水平数据及来源说明 | Scope 活动记录、能源事实、供应链数据 | 记录活动量、单位、期间、来源、监测频次和证据。 |
| 排放因子与计算参数说明 | `factor_library`、计算结果快照 | 记录因子、参数、标准来源、适用期和置信等级。 |
| 数据质量控制与文件存档 | 审核日志、质量问题、计量与校准附件 | 说明监测计划、缺失处理、内部复核、版本锁定。 |
| 附表 A-F | 业务数据附表 | 承载主体、活动数据、燃料、电热、过程排放、因子参数。 |
| 附表 G-J | 核查支撑附表 | 承载材料包目录、文件评审底稿、现场核查清单、不符合项整改。 |
| 附表 K-N | 系统实现附表 | 承载领域映射、模板字段、ZIP 文件树和后续实现拆分。 |

## 4. 导出上下文

正式导出应优先读取已发布组织边界和已锁定组织排放清单。为了兼容当前首版实现，`carbon_verification` 可以继续从 Scope 活动记录生成读模型，但正式报告的目标路径应收敛为：

```text
organization_boundary
  -> carbon_accounting.batch
  -> carbon_accounting.inventory_items
  -> carbon_verification.report_context
  -> carbon_verification.ReportDocumentRenderer
  -> carbon_verification.MaterialPackageAssembler
```

关键字段：

| 字段 | 来源 | 缺失处理 |
| --- | --- | --- |
| `enterprise.name`、`enterprise.unify_code` | `EnterpriseInfo` | 缺失时阻塞正式导出。 |
| `reporting_period.year`、`period_start`、`period_end` | `ReportingPeriod` 或查询筛选 | 无报告期时只能导出草稿。 |
| `boundary_version`、`included_facilities`、`excluded_sources` | `OrganizationBoundary`、`BoundaryFacility` | 无已发布边界时阻塞正式导出。 |
| `inventory.scope_summary`、`inventory.source_summary` | `CarbonEmissionInventoryItem` | 无清单时返回 `empty_inventory`。 |
| `activity_data[]` | 清单快照或 Scope 活动记录 | 缺活动数据进入 `blocked`。 |
| `factor_parameters[]` | 因子库、计算结果快照 | 缺因子进入 `missing_factor`。 |
| `evidence_manifest.items[]` | 当前附件字段，后续 `VerificationAttachment` | 缺凭证进入 `missing_evidence`。 |
| `quality_issues[]` | `carbon_verification.issues` | 可导出，但状态应为待完善或阻塞。 |
| `audit_trail.items[]` | `CarbonAuditLog`，后续核查复核日志 | 无记录时写明“未形成独立复核记录”。 |

## 6. 后续实现拆分

| 对象/服务 | 所属上下文 | 职责 | 验收口径 |
| --- | --- | --- | --- |
| `ReportTemplateVersion` | `carbon_verification` | 管理模板名称、版本、标准来源、适用行业、文件路径和启停状态。 | 导出任务记录模板版本，历史报告可复现。 |
| `ReportDocumentRenderer` | `carbon_verification.usecases` | 读取 `report_context`，填充 DOCX，转换 PDF，计算文件哈希。 | ZIP 中真实包含 DOCX/PDF，字段缺失返回业务状态。 |
| `VerificationAttachment` | `carbon_verification` | 管理凭证原件、来源对象、文件类型、哈希、OCR/备注和版本。 | 材料包能打包原件，缺失凭证可追踪到活动记录。 |
| `VerificationFinding` | `carbon_verification` | 承载文件评审、现场核查、不符合项、整改和关闭状态。 | 自动问题可升级为可关闭的核查发现。 |
| `MaterialPackageAssembler` | `carbon_verification.usecases` | 汇集报告、数据表、附件、问题和审核轨迹，写入导出清单。 | 导出任务可重试、可下载、可校验。 |
| `InventorySnapshotReader` | `carbon_verification.queries` | 优先读取已锁定组织排放清单，兼容旧 Scope 活动记录。 | 正式导出不绕过边界版本和清单锁定。 |

## 7. 开发顺序

1. 增加模板版本配置，当前通用模板作为 `organization_ghg_generic_v2026_06_13`。
2. 新增 DOCX 渲染 usecase：填充段落、表格、动态行和占位符，输出临时 DOCX。
3. 使用 LibreOffice 或后续文档渲染服务把 DOCX 转为 PDF。
4. 将 DOCX/PDF 写入 `CarbonVerificationExportFile`，更新 ZIP manifest 和文件哈希。
5. 新增 `VerificationAttachment`，把附件原件加入 `evidence/{year}/`。
6. 将当前自动问题升级为 `VerificationFinding`，支持整改、复核、关闭。
7. 让正式导出优先读取已锁定 `CarbonAccountingBatch` 和 `CarbonEmissionInventoryItem`。
