# 祥泰、安方真实数据录入与迁移实施手册

- 更新时间：2026-08-10
- 实施状态：代码完成，待生产变更审批与执行
- 首批租户：祥泰仓库、安方中心库
- 规范化起点：2026-05-01
- 数据原则：旧来源只读保留、派生结果版本化、开发期记录内部隔离、租户数据不混用

## 1. 实施范围

本手册用于把祥泰和安方的电表读数、区域设备主数据、能源投影和 Scope 2 对账接入正式数据链。姜堰、泰兴在施工验收后复用同一工作簿和命令。

本次包括：

1. 修复生产数据库结构与 Alembic 版本登记不一致。
2. 导入区域、设备/设备组、电表绑定、用能系统和计量边界。
3. 从 2026-05-01 起影子迁移祥泰独立旧表来源；安方不重复迁移 MQTT 兼容记录。
4. 切换并核对 Yunji、MQTT 统一写入。
5. 生成小时、日、月能源事实及 Scope 2 月度对账。
6. 让能源查询、分析、能流、平衡、预算和碳核算统一读取当前正式版本。

本次不包括：

- 删除 2026-05-01 前约 133 万条祥泰旧表记录。
- 删除 `dataapp_ammeterindexvalue`、`dataapp_iottelemetry` 或 17 个旧统计视图。
- 将安方 22,767 条 MQTT 兼容旧表记录再次迁入统一事实。
- 用数据库 downgrade 回退。
- 未经客户凭证确认，将开发期活动数据转为正式数据。

建议安排 30 分钟低峰变更窗口，其中采集 worker 实际暂停不超过 5 分钟。业务查询页面保持可读。

## 4. 生产预检与外部备份

所有命令先在部署目录执行，数据库连接由生产环境变量提供。禁止把连接密码写入仓库或本手册。

### 4.1 保存部署和结构基线

```bash
date -Iseconds
git rev-parse HEAD
docker compose ps
uv run app database show-current-revision
df -h /
```

保存以下 SQL 输出到变更工单附件：

```sql
select version_num from ddl_version;
select pg_size_pretty(pg_database_size(current_database()));

select team_id, count(*), min(data_time), max(data_time), max(id)
from dataapp_ammeterindexvalue
group by team_id
order by team_id;

select team_id, count(*), min(received_at), max(received_at), max(id)
from iot_mqtt_inbound_message
group by team_id
order by team_id;

select team_id, count(*), min(reading_time), max(reading_time), max(id)
from metering_meter_reading_fact
group by team_id
order by team_id;
```

另外保存关键表结构指纹：

```bash
pg_dump "$DATABASE_URL" --schema-only --no-owner --no-privileges \
  | sha256sum
```

### 4.2 加密逻辑备份

服务器磁盘已使用约 85%，备份不能只留在当前服务器。将自定义格式逻辑备份通过加密通道写入已确认的外部存储，并在外部存储校验文件大小和摘要。

```bash
pg_dump "$DATABASE_URL" --format=custom --no-owner --no-privileges \
  --file /external-backup/warehouse-before-metering-$(date +%Y%m%d%H%M%S).dump
sha256sum /external-backup/warehouse-before-metering-*.dump
pg_restore --list /external-backup/warehouse-before-metering-*.dump | head
```

`/external-backup` 必须是外部挂载或备份服务落点。若先生成本地临时文件，外传并验证后立即按运维制度清理，不能长期占用生产盘。

## 5. 数据库迁移

1. 部署包含迁移 `9a0b1c2d3e4f` 的应用镜像，但暂不恢复采集 worker。
2. 执行升级：

```bash
uv run app database upgrade --no-prompt
uv run app database show-current-revision
```

3. 版本必须为 `9a0b1c2d3e4f`，并验证保留表与正式视图：

```sql
select to_regclass('dataapp_ammeterindexvalue');
select to_regclass('dataapp_iottelemetry');
select to_regclass('metering_meter_reading_fact');
select to_regclass('energy_consumption_fact_all_v');
select to_regclass('energy_consumption_fact_v');
```

`energy_consumption_fact_all_v` 是保留历史来源的内部底层视图；业务查询使用 `energy_consumption_fact_v`。后者排除内部参考活动记录，只读取当前月度聚合，并按当前对账结果在电费单和电表聚合之间二选一。

## 6. 主数据录入

### 6.1 工作簿顺序

使用当前租户会话下载模板：

```text
GET /api/master-data/import-workbooks/template
```

按以下顺序填写七张表：

1. `01_区域`
2. `02_设备设备组`
3. `03_电表绑定`
4. `04_用能系统`
5. `05_用能系统绑定`
6. `06_计量边界`
7. `07_边界成员`

工作簿不能指定租户。导入器只使用当前登录会话的租户，整本原子提交，按租户内编码幂等更新，不删除失效对象。

### 6.2 预览和导入

将 `.xlsx` 文件进行 Base64 编码后，以 `workbook_base64` 字段请求：

```text
POST /api/master-data/import-workbooks/preview
POST /api/master-data/import-workbooks/import
```

必须先通过预览。跨租户引用、重复编码、循环区域树、无效日期、未知设备/区域/系统引用必须拒绝。

### 6.3 两租户规则

- 祥泰：保留现有 17 个详细点位节点及电表关系，不用安方模型覆盖。
- 安方：导入 `HMAZ`、平置库/立体库和方位区域、8 块电表正式业务名称、用能系统及计量边界。
- M002、M006、M007、M008：区域和用途先启用；具体物理设备成员保持 `candidate`，现场确认后改为 `confirmed`。
- 倍率必须明确是上游已折算还是平台折算；计量方向首期为购入分项。

## 7. 历史读数影子迁移

### 7.1 祥泰

先执行只读预估：

```bash
uv run app metering migrate-legacy \
  --team default-tenant \
  --from 2026-05-01 \
  --batch-size 10000 \
  --dry-run
```

核对来源行数和八个非空字段预计事实数后执行正式迁移：

```bash
uv run app metering migrate-legacy \
  --team default-tenant \
  --from 2026-05-01 \
  --batch-size 10000
```

迁移按旧表 ID 保存高水位和断点，使用确定性 `source_record_id`。中断后重复执行同一命令会续跑，冲突记录跳过；旧表不更新、不删除。

### 7.2 安方

安方不运行 `migrate-legacy`。验证原始消息、8 块表、20 点事实和绑定：

```sql
select count(*) as messages from iot_mqtt_inbound_message where team_id = :anfang_team_id;
select count(*) as facts from metering_meter_reading_fact where team_id = :anfang_team_id;
select count(distinct (equipment_id, point_code)) as meter_point_pairs
from metering_meter_reading_fact
where team_id = :anfang_team_id;
```

截止高水位应满足：消息对应 8 块表和 20 个点位、事实无孤立消息/设备绑定、同一来源事实不重复。

## 8. 采集切换

1. 记录暂停前 MQTT 原始消息最大 ID、接收时间，及每块 Yunji 电表最后成功时间。
2. 暂停 MQTT 和 Yunji worker，控制在 5 分钟内。
3. 确认应用版本只向 `metering_meter_reading_fact` 写统一事实。
4. 恢复 MQTT worker，核对持久会话、QoS 和待处理消息补发。
5. 恢复 Yunji worker。任务会遍历全部启用的 Yunji 电表，按每表游标、15 分钟重叠和最大 24 小时窗口补拉。
6. 观察新增原始消息、事实、重复冲突和游标状态至少一个采样周期。

异常时恢复上一应用/worker 镜像；已写入的原始消息和统一事实保留，不执行数据删除或数据库降级。

## 9. 能源与 Scope 2 投影

主数据导入和读数验收后，分别在两个租户执行：

```bash
uv run app metering project-electricity \
  --team default-tenant \
  --from-month 2026-05 \
  --to-month 2026-08

uv run app metering project-electricity \
  --team anfang-center-warehouse \
  --from-month 2026-07 \
  --to-month 2026-08
```

命令对累计表码按租户、电表、标准点位和时间排序，生成质量问题、小时/日事实、月度分表聚合及对账修订。重复执行且来源与映射未变化时复用原投影；来源或映射变化时创建新修订，旧修订保留审计。

真实电费单导入并审批后，系统为该月生成新的账单优先对账版本：

- 组织总量使用已审批正式账单合计。
- 分项电表用于区域和用途分配。
- 账单大于有效分项之和的差额进入未分项电量。
- 旧的电表暂用对账继续保留，但正式查询不会与账单同时累计。

## 10. 验收清单

### 10.1 迁移完整性

- 祥泰目标事实数等于高水位内八个来源字段的非空总数。
- 祥泰旧表迁移前后行数、最大 ID 和抽样摘要不变。
- 安方原始消息、160 个电表测点组合和统一事实数量关系一致。
- 安方没有孤立消息、设备绑定或跨租户事实。
- 工作簿重复导入不新增重复区域、设备、系统、边界或成员。

### 10.2 投影和对账

- 同一来源、月份和映射重跑结果不变。
- 任一当前小时/日/月事实只有一个 `is_current=true` 修订。
- 历史修订可通过审计查询读取，但能源业务页面不重复累计。
- 候选边界成员不参与正式设备级分配。
- 月度组织电量等于当前对账来源；区域与用途分配不超过组织总量。
- 有正式账单时电表暂用版本被替代，而非删除。

### 10.3 租户与页面

- 祥泰、安方切换租户后，区域、设备、读数、能流、排放和大屏结果互不可见。
- 能耗、分析、能流和平衡读取 `dataapp_energyintervalfact.is_current=true`。
- 综合能耗、强度、预算和对标读取正式 `energy_consumption_fact_v`。
- 碳活动正式查询不读取 `record_usage=reference` 的开发期记录。
- 客户页面不显示 `demo`、`mock`、`seed` 等内部来源描述。

## 11. 回滚

本次迁移不提供数据库 downgrade。发生异常时按以下顺序处置：

1. 停止新版本采集和投影 worker。
2. 恢复变更前应用和 worker 镜像。
3. 业务查询恢复上一发布版本；旧表和旧视图仍在，可继续只读服务。
4. 保留新写入的原始消息、统一事实、迁移运行和投影修订，后续通过幂等命令续跑或重新投影。
5. 只有数据库结构本身不可用且应用回退无法恢复时，才按变更审批从外部逻辑备份恢复到新数据库并切换连接；不得直接覆盖唯一生产库。
