# 祥泰真实数据补全计划与执行记录

后续进度：用户要求按既有区域设备范围执行后，156条活动已完成计算并生成两份报告，见[计量范围核算执行记录](xiangtai-meter-calculation-20261013.md)。下文保留第一批草稿整理时的状态，不能当作最新核算状态。

## 结论与范围

本轮在 `warehouse.nexlca.com` 对应华为 `/root/warehouse` 生产数据库执行，不是在本地造演示数据。完成的是**真实计量活动整理**，不是完整组织碳核算验收。

- 由 110,518 条当前有效小时事实，生成 156 条逐表逐月活动草稿，覆盖 13 个计量对象、2025-07 至 2026-09。
- 建立 23 条按年度盘查任务划分的排放源、156 条区域设备归集、2 个草稿报告期、2 条官方因子参数及来源附件关联。
- 156 条活动均为 `draft`，`boundary_status=excluded`，未生成正式核算运行或报告。ISO 2.1 是待核实购电属性的候选分类，不代表已经确认全部电量都是组织外购电。
- 不恢复已删除的 67 条演示活动，不修改原始示值，不重建区域层级，不推断电气上下级，不使用名称判断总分表，不修改安方核算数据。

本轮只读取 `meter_projection/hour`，不与 `meter_hourly`、`meter_daily` 或 `meter_projection/day` 混加。当前 2026-10 月尚未结束，未纳入这次封闭月份批次。

进一步核对线上规范化原始事实：`yunji/register_index` 正向有功总示值444,752条，起于2025-07-01；`yunji_legacy/register_index` 同类示值40,983条，仅覆盖2026-07-10至2026-08-10。因此更早旧版能源汇总和红外表不能通过简单重跑当前小时投影补齐，需先将旧SQL中对应原始示值按来源ID导入规范化事实并核验，再使用同一投影流程重建。本轮未执行这项历史回灌，也未把云集月份套给红外表。

## 后续核算的最小输入

1. 电费账单：计费月、购电量、户号、供电方及覆盖仓库/设施。若账单作为购电活动，已有分表只作内部归集依据，不能再次叠加到总量。
2. 或提供进线表编码及确认的计量范围：哪些是分表、光伏发电表、储能充放电表，倍率与生效日期是什么。按已确认的不重叠集合建立现有计量边界，不新增旁路表。
3. 确认组织控制范围并发布现有核算边界；复核所选期间活动和因子后执行既有核算用例，最后生成报告并验收大屏。

这些是不同的取证途径，不要求先建设复杂对账流程。未取得依据前，不将13个计量对象电量相加冒称组织购电总量。
