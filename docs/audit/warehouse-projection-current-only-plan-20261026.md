# 仓储能源投影取消历史版本与 OOM 治理方案

日期：2026-10-26（北京时间）。状态：代码、本地测试、生产历史清理、约束升级、部署及 15:10 自然定时验收均已完成。实施证据见 `warehouse-projection-current-only-validation-20261026.md`。

## 1. 目标与范围

按用户决定，自动生成的能源投影只维护当前结果，不再创建、保留逐次计算的历史版本。删除已有失效版本，同时保留原始读数、必要的执行日志和正式业务凭证。

| 对象 | 目标行为 |
| --- | --- |
| `dataapp_energyintervalfact` 小时／日统计 | 相同业务键一行，更新或新增；失效结果删除；禁止整月追加副本 |
| `dataapp_scope2meteraggregate` 电表月度汇总 | 每租户、电表、月份一行，维护当前值 |
| `metering_scope2_electricity_reconciliation` 月度对账 | 每租户、月份一行，维护当前值 |
| `metering_meter_reading_fact` 原始读数 | 保留，不纳入版本清理 |
| `metering_energy_projection_run` 执行记录 | 保留水位、输入摘要、计数、耗时、峰值、状态和错误；不保存整套结果副本 |
| 正式报告、已确认分摊及其业务快照 | 保留既有凭证；与可变的实时投影解耦，不建立新的能源历史事实表 |

本次不改变累计表差分、异常读数处理、小时归桶、计量边界、模拟数据标识或账单优先级。计量语义沿用现有实现及 `docs/评价方案/祥泰安方真实数据录入与迁移实施手册.md`；该文档中的投影修订条款随实施更新。资源预算、批大小、冷却时间是运维配置，不是计量标准。

## 2. 已有证据与边界

线上两个关键文件与当前本地代码 SHA256 一致。生产只读统计显示：

| 租户／2026-10 | 小时总版本数 | 当前小时数 | 日总版本数 | 当前日数 |
| --- | ---: | ---: | ---: | ---: |
| 祥泰 | 770,980 | 5,050 | 33,170 | 220 |
| 安方 | 609,216 | 4,040 | 26,208 | 176 |

上述两个租户的该月 `meter_projection` 合计 1,439,574 行，其中当前记录 9,486 行，失效版本 1,430,088 行，约占 99.34%。这是诊断时点的候选规模，不是最终删除清单；其他月份、来源和引用情况尚须盘点。

改造前实现根据整月校验和决定重建，重建时对所有输出追加新版本，并把匹配的完整历史加载成 ORM 对象。旧代码各阶段峰值未在线重新复现；新实现的生产阶段 RSS、重复执行和队列追赶证据见验收记录。

## 3. 实施前盘点与短期保护

1. 从生产实际 schema 导出三张表的唯一约束、索引、外键、视图、RLS 和触发器。查询按租户执行，设置 statement/lock timeout，不在生产运行旧重建代码。
2. 按租户、月份、来源统计当前／失效记录、重复当前键、仅有失效版本的键、历史引用和金额／电量摘要。清理清单固定到 ID 截止点并落盘。
3. 核对数据库外键之外的引用：JSON 快照、业务类型加 record_id、报表、物资分摊、导入与导出。当前已确认物资分摊快照包含事实 ID、revision；导入 SQL 使用 `uq_energy_interval_team_source_record_revision`。
4. 本地文档提及正式碳核算锁定引用，但当前工作区相关目录只发现缓存文件，不能凭文档认定生产实现完整。以线上镜像、实际表与消费代码为准核对。
5. 实施窗口单独暂停／阻断 `refresh_electricity_projections`，覆盖 cron、已排队任务和手工 CLI 入口；确认无在途重建，避免旧写入器与清理竞争。其他采集、OAuth、预测等任务继续运行。若开关需要 worker 重启，先评估在途任务并安排短暂受控重启，不直接停掉整个 worker。
6. 容器资源限额单独实施和验证。暂定 1.5 GiB 硬上限作为候选，待核对同进程其他任务峰值后确定；超限仍可能中断该 worker 的其他任务，因此它只承担宿主机保护。

## 4. 当前结果写入设计

### 4.1 唯一键与字段

- 小时／日事实：`(team_id, source_system, source_record_id)` 唯一；投影 source_record_id 继续由设备、粒度、时间确定，避免无关来源合并。
- 电表月汇总：`(team_id, ammeter_id, billing_month)` 唯一。
- 月度对账：`(team_id, billing_month)` 唯一。
- 保留当前记录 ID；有变化原位更新，无变化不写，新区间插入。因源数据无效或边界变化而消失的区间，从本次明确处理的范围内删除。
- 旧 `meter_hourly`／`meter_daily` 与 `meter_projection` 的重叠数据按原替代关系治理；人工、导入及其他来源不能仅凭相同设备和时间合并。
- 迁移过渡期可保留 `revision_no/is_current/supersedes_id` 兼容列，新记录为 `1/true/NULL`；迁移保留当前行原有 revision_no 并停止递增、清空 supersedes_id，以维持既有盘查事实哈希，不承担版本能力。新增不含 revision 的唯一约束保证无法继续追加版本。
- 完成全部调用方迁移后，再用独立迁移删除兼容字段和这三类模型的版本过滤。其他领域的版本机制不在本次删除范围内。

### 4.2 有界计算与原子发布

- 以租户、月份为发布单元，按设备及读取时间流式取数；只选计算需要的字段，禁止隐式加载设备／区域关联树。
- 初始读写批量设为 1,000 行，可配置；边界处保留前一有效样本、重复时间戳候选、固定值持续状态及未结束的小时／日桶，保证分批前后结果一致。
- 不再构造整月 ORM 对象列表、完整问题列表或历史版本字典。质量问题及输出分批写入／flush，及时释放对象。
- 必要时用事务内临时表承接当前运行结果，不能以历史事实表作为暂存。临时结果不供业务查询，不形成持久版本库。
- 当前结果替换、消失区间删除、月汇总、对账和成功水位必须在同一发布事务提交；失败回滚，读者继续看到上一次完整结果。不得用分批 commit 暴露半个月新旧混合数据。
- 使用一致性输入快照或明确的读数截止水位，确保扫描后新增读数留到下一轮；元数据摘要也参与变化判断。
- 本次实现使用流式整月输入校验和逐电表计算、差异写入；仅扫描受影响时间窗口的优化留作后续，不作为本次取消版本与内存治理的前置条件。迟到读数同时影响前后相邻区间，跨月锚点也须纳入。映射或算法变化可触发完整有界重算，不只依赖 `max(id)` 判断是否有变化。
- 月度对账幂等摘要不能继续只比较 aggregate ID：当前记录 ID 将保持稳定，摘要必须包含影响结果的数值、账单内容和有效配置。
- 成功输出计数按运行日志或业务范围计算，不能再用 `projection_run_id` 查询旧版本来还原某次运行结果。

### 4.3 下游数据一致性

当前 ID 稳定后，分摊／分析缓存必须用内容摘要识别输入变化，不能用“ID 或 revision 没变”认定输入未变。更新源电量时标记受影响的可重算结果；已确认／锁定凭证保持原快照，按原业务流程处理修订。

删除历史源行前检查正式凭证是否具备独立完整快照。缺失时先补齐凭证所需内容，保留原始来源标识；不能将旧凭证静默改指向数值不同的当前行，也不能依靠外键 `SET NULL` 静默破坏追溯。

## 5. 历史数据清理

1. 完成代码及迁移演练后，在暂停投影写入的窗口重新生成 dry-run 报告：保留数、删除数、冲突数、引用影响、当前电量摘要。
2. 用户于 2026-10-26 明确授权不备份失效派生版本，直接清理。保存当前内容摘要、删除数量及配置回退文件，不创建历史重复数据备份。
3. 每个业务键恰有一个当前行时保留该行及 ID，删除其他版本。一个键没有当前行，表示现有结果已撤销，其旧版本全部纳入清理，不能选最大 revision 复活。多个当前行进入异常清单，根据原始数据与既有语义确定结果，不以最大 ID 猜测。
4. 先处理引用和 `supersedes_id` 链，再按租户、主键分批删除；初始每批 2,000 行，独立短事务，可暂停、可恢复、重复执行无副作用。遇锁等待、主机内存不足或数据库负载升高则暂停。
5. 在旧唯一约束仍存在时，先删除冲突旧版本，再清空保留行的版本链；冻结原有 revision_no，避免无业务变化却使既有凭证哈希失效。随后建立不含版本号的唯一约束，并同步导入 SQL 的 `ON CONFLICT` 目标。新约束未就绪前不得恢复写入。
6. 清理前后按租户／月份／设备／粒度核对当前行 ID 集合、计数、电量和内容摘要。清理本身不得改变当前业务数值。追赶重算另行记录新旧数值差异及来源。
7. 完成普通 VACUUM/ANALYZE，检查索引与执行计划。DELETE 不保证操作系统磁盘立即缩小；在线验收不使用阻塞式 VACUUM FULL，磁盘压缩另排维护窗口。

执行工具应支持 `dry-run`、租户／月份过滤、批大小、限速、断点、引用冲突报告和校验报告；不能一次全表 DELETE 或将数百万 ID 拉到 Python 内存。

## 6. 重试、互斥与监控

- 同一租户只允许一个重建，兼容整月／区域任务重叠；使用非阻塞锁，取锁失败即跳过，避免任务堆积。
- 在重算事务外持久记录运行中状态与 2100 秒租约（SAQ 任务超时 1800 秒）；异常、超时、进程被杀后均可识别失败，不依赖进程内变量。
- 失败按租户／月份退避，建议初始 1 小时、再次 6 小时、连续 3 次打开熔断并告警，人工解除后才恢复该月份；其他月份／租户可继续。以上为可配置运维策略。
- 成功水位只随完整发布推进；失败不假装完成，不因 worker 重启立即重复同一高负载月份。
- 记录读取／计算／写入／对账／提交阶段的行数、当前 RSS、RSS 增量、进程峰值、耗时、租户、月份、输入水位及插入／更新／删除数量。结合容器采样识别并发任务的影响，不能将进程 RSS 全部归因于单个任务。
- 候选验收预算：投影运行期间 worker 峰值不超过 768 MiB，容器硬上限候选 1.5 GiB；以隔离压测和实际并发验证确定最终值。应用超预算先中止并冷却，硬上限作为最后防线。
- 新问题记录也应按来源事实和问题类型幂等处理，避免将版本膨胀转移到质量问题表。执行日志保持轻量并制定保留策略。

## 7. 发布顺序与回滚

顺序固定：完成引用盘点 → 本地实现和隔离测试 → 暂停投影写入并确认无在途任务 → 清理失效版本 → 安装新约束和适配代码 → 小范围追赶验收 → 恢复调度 → 验证后续周期 → 后续删除兼容字段。

上线包必须覆盖 worker、手工 CLI，以及受约束变化影响的 app 导入／写入端；不能只更新 worker 留下使用旧约束的 app。发布时保留生产 app 现有的独立修复，禁止用未经核对的 worker 镜像覆盖 app。

失败时立即暂停投影，业务继续使用最后完整发布的数据；采用向前修复或恢复相互匹配的代码和约束。不能只回滚成仍追加历史版本的旧 worker。上线后新采集的原始读数应保留，不用整库回滚覆盖它们。被清理的历史内容不能靠 Alembic downgrade 自动恢复。

## 8. 验收清单

- 三张目标表按新业务键无重复，不再存在失效版本；其他租户和其他来源无越界删除。
- 清理前后当前电量和业务摘要一致；正式凭证和分摊快照可继续读取。
- 相同输入重复运行不增行、不改变内容摘要；新增读数只新增必要区间，修正读数原位更新，失效区间删除。
- 跨批次／跨月、重复时间戳、读数复位／缺口、模拟来源、区域边界变更、账单变化测试结果符合原计量语义。
- 租户读写隔离、原子回滚、进程中断恢复、并发互斥、冷却与熔断通过测试。
- 使用覆盖实际规模并额外放大的隔离数据进行内存测试，不在线重放旧危险路径；读取、问题生成和写入峰值均受预算约束。
- 祥泰、安方待处理月份逐个成功完成，成功水位推进。
- 至少两个后续定时周期成功；有新读数时完成更新，无变化时跳过，行数不随执行次数倍增，无 OOM、长时间锁等待或冷却重试风暴。

只有上述数据、任务和资源验收完成，才将本次事故标记为已解决。

本次用户明确豁免历史重复数据备份，执行入口使用 `--backup-waived`，不冒充已经验证备份。已删除派生历史不提供数据回滚；原始采集读数、当前结果及原有业务快照保留。
