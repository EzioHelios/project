# 大屏组件复刻第一批实施与验证记录

日期：2026-10-12。依据：[组件清单](bigscreen-component-replication-plan-20261012.md)。

## 1. 验收结论

本地已完成能源投影时效修复及第一批可由现有记录支撑的展示组件。四个主题为态势总览、视频监控、电量监控、碳排管理，另保留仓库档案和模型全屏。没有运行演示造数，没有给安方复制祥泰档案，没有更新线上环境。

**第一批不能整体标记为全部完成：祥泰总分表计量边界仍待业务确认；旧版远程报表未恢复，图表精确样式只能部分比对；视频目录不等于已验证实时播放。**

本地入口：<http://127.0.0.1:18101/bigscreen/overview>。后端使用本地容器；生产环境只用于只读调查及导出现有采样。

## 2. 能源链路修复

- 根因：电表采集持续执行，但能源投影未接入周期调度。采样已有10月数据，而原能源投影停在8月。
- 新增 `domain/metering/jobs.py`，按租户检测已完成投影的采样高水位，补算新增/迟到采样月份；每租户每轮最多三个月份，最新月份优先。复用现有投影用例，不新建事实表。
- 在两个既有 SAQ 启动入口注册同一任务，每小时10分、40分执行。单租户失败回滚并记录，不阻止其他租户执行。
- 投影版本更新为 `boundary_v2`，校验和包含采样来源、设备区域关系。任一相邻读数来自 `demo*`，对应区间标记为 `simulated`，日汇总保留该标记。
- 大屏仅读取当前版本电表能源事实；小时与日事实分开查询，月趋势汇总日事实。排除演示来源、模拟质量、手工能源台账，避免并入第二套录入数据。
- 区域筛选沿实际父子ID展开；缺测是断点，不以0填充。默认选最新已有能源事实所在月份，并明确截至日期。
- 最近采样、能源投影更新时间和页面时钟分别展示，不将“台账正常”或“24小时有采样”冒充实时在线。

## 7. 尚未完成及上线条件

1. **祥泰计量边界待确认**：线上无边界配置；本地 `XT-SITE-ELECTRICITY` 未绑定电表。不能按名称猜总表/分表。本轮展示电表合计，不宣称已修好仓库总量口径。既有投影的无边界Scope2暂存行为未重构，碳大屏不以它作为正式结果。
2. **安方原始资料待补**：企业档案、照片、摄像头、经营和通勤记录缺失；不借另一租户数据。区域设备准确性、表计倍率仍须现场确认。
3. **祥泰视频事件数据待核实**：旧模型事件类型3为“火点”，但部分记录描述为“异常跌倒”。保持原始记录，不自行改码。摄像头目录和台账正常状态不能证明视频流可用。
4. **第二/三批未实施**：视频播放/轮播、摄像头空间坐标、GIS与指标双向联动、光伏/充电/储能计量补齐、经营碳强度、全年碳趋势。
5. **未部署**：本轮只重启本地应用容器；未重启线上或本地Worker。新增周期任务要在发布后重启Worker才生效，尚无真实定时调度执行证据。手动调用现有投影用例已经验证。
6. **上线不需新增迁移**：本轮无模型表结构变化。发布后先核实边界和照片持久化，再对确定租户执行现有 `app metering project-electricity --team <slug> --from-month 2026-10 --to-month 2026-10`，核查日志及幂等结果，最后验证Worker周期执行。不要把本地初始化的祥泰碳数据直接覆盖生产数据。
