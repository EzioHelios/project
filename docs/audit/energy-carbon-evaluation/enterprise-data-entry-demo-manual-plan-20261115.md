### 实施核对后确定的处理

- 员工通勤档案目前没有日期、报告期或出勤频次。它不能直接生成指定月份的通勤总量；本轮通过 3.3 分类表单和模板填写当期数据，不保留点击后必然跳过的生成入口。运输同样按有期间、有数量的业务记录填报。
- 电力、天然气和柴油使用能源台账生成入口。制冷剂不是能源消费品种，旧演示包反填到能源事实中的制冷剂记录须按演示对象归属清理；不影响安方、祥泰等业务租户。
- 浏览器核对发现旧逸散排放记录气体显示为 CO₂e、分类设备字段为空且按月生成。演示包改为明确设备、日期、制冷剂种类与维修量的事件；保留实际零值与未填写的区别。
- 碳分类列表只展示该类必要字段，完整信息在详情查看。通勤不显示货物质量，货运不显示人数；库存平衡字段不占据逸散排放列表的主要位置。

## 1. 本轮目标

先解决三个问题：企业知道在哪里填数据；保存、导入后能够直接找到并修改这些数据；演示案例使用清楚、合理的工厂对象和数据。证据材料、审核流程、合规检查不作为本轮主线或新增前置条件。

方案编制阶段核对了演示生成代码、活动表单和导入页面、已发布手册、两仓历史维护记录，并抽查用户提供的真实工作簿及部分内嵌图片；当时没有重新查询线上生产数据库，也没有逐张识别全部原始材料。后续发布阶段的生产检查和已修复问题另见发布记录，下述问题表保留方案编制时的依据。

## 2. 已确认的问题

| 层面 | 现状及依据 | 对企业用户的影响 |
| --- | --- | --- |
| 演示数据生成顺序 | `demo/showcase/builder.py` 按活动类别基数、年度系数、季节函数生成月度碳活动；`demo/ops/woheng.py` 又从部分非电碳活动生成能源事实 | 能展示图表，但不能自然说明企业如何从一张燃气或柴油台账逐步得到分析结果；演示过程与日常维护顺序不一致 |
| 数据业务含义 | 同一月度生成函数用于电力、燃料、制冷剂等；内部活动普遍写为“计量系统月结” | 制冷剂补充等事件型数据被做成规则月度曲线，采集方式也不够贴近实际 |
| 中文显示 | 演示包写入 `supplier_ledger`，`ghg-maintenance.tsx` 的 `sourceLabel` 未覆盖此值；未匹配值直接显示原字符串 | 英文既来自演示数据，也来自不完整的显示映射，不能只改种子名称解决 |
| 对象显示 | 导入预览直接显示 `organizationCode`、`facilityCode`、`areaCode`、`equipmentCode`；详情“排放源”显示 `sourceCode` | 用户必须记住编号，无法直接判断是哪座工厂、哪个车间、哪台设备 |
| 表单 | 活动表单已有分类动态字段和部分中文选择项；没有 choices 的设备、计量点、运输方式等字段统一使用普通输入框，单位也为自由输入 | 不是所有分类都仍需手输，但已有主数据未充分用于选择；容易写出不同名字或单位 |
| 保存反馈 | 新增、修改后刷新查询并提示“已保存/已更新” | 缺少刚刚保存的记录定位、修改前后数值和后续查看入口 |
| 导入反馈 | 导入页有预检、警告、已入库状态和执行核算按钮；入库后仍主要展示预检表，台账链接仅携带分类 | 有反馈，但用户还需自行搜索本次数据，看不到清楚的新增记录范围及数量、分能源用量和对应设备 |
| 重复导入 | 同一个已提交批次再次提交会返回原批次；新批次发现已有记录编号则拒绝写入 | 不能笼统称为可重复更新；企业改错后重传的处理方式需要明确 |
| 手册 | 导入章节集中解释组织、排放源、活动、归集、参数和证据等工作表，却没有同一实例的原表、填写表、导入结果、修改结果连续展示 | 用户读到的是字段说明，仍不知道自己的一张表如何变为系统中可查询的数据 |
| 截图案例 | `verify-ghg-maintenance.mjs` 使用“手册验证购入电力活动”和 `MANUAL-GHG-*` 等测试内容 | 测试能验证按钮，不适合作为正式教学案例；截图通过不等于业务说明清楚 |
| 演示验收 | demo validate 已有多种数量门槛、能源类型诊断和旧品牌检查 | 仍不足以证明“从企业原表导入得到同一批业务数据”；不能只以记录数和截图数验收 |

供应链文件中同时包含产品级材料和企业级用能资料。本轮优先取企业级用能、设备和活动台账的结构；不把产品碳足迹结果相加作为组织排放。

## 4. 企业操作流程

统一为：选择工厂和月份 → 选择数据种类 → 手工新增或导入 → 查看本次保存的数据 → 修改、删除或继续录入 → 查看能源汇总/生成组织碳活动 → 执行核算并查看排放。

### 4.1 数据分别在哪里维护

| 企业手里的数据 | 唯一主要维护位置 | 保存后看到什么 |
| --- | --- | --- |
| 电费电量、天然气、汽油、柴油等月度用量 | 现有能源数据维护页 | 对象、月份、能源品种、用量、单位、费用；按能源品种分别汇总 |
| 电表自动采集 | 现有设备与测点配置、能源查询 | 表计最近读数、对应设备和区域、期间用电量；与手工月度数据明确区分 |
| 制冷剂补充/回收、其他非能源活动 | 现有对应分类填报页 | 设备/活动对象、日期、物质种类、实际数量、单位及业务必要字段 |
| 通勤、运输等当期经营记录 | 3.3 员工通勤、3.1 运输分类表单或本类模板 | 按期间整理的交通方式、距离、人数或质量、活动量；本轮不自动投影没有期间的旧档案 |
| 计算后的排放 | 现有组织碳核算页 | 按月份、能源/活动类别、区域和设备查看排放；能返回相关活动记录 |

能源事实与碳活动之间的生成继续复用现有模型和用例，补齐明确入口、重复执行规则和返回结果，不新增另一套用量台账。已存在功能先确认可用再补；不把后台批量插入等同于页面录入跑通。

### 4.2 页面先改的内容

1. 列表以中文对象名称、月份、能源或活动名称、数量和单位为主；编号放在次要位置。供应商、区域、设备和排放源均显示名称。
2. 设备、区域、能源种类、可选单位使用统一选择器；编码由系统维护。R32、SF6、kWh及真实型号等有业务含义的字符保留。
3. 保存成功后直接定位该条数据，显示保存值；编辑后回显新值；删除后刷新同一筛选结果和对应汇总。
4. 分类导入采用一张主要填报表，固定的工厂、期间和分类由页面带入；用户填写对象、月份、数量、单位及本类必要字段。现有复杂工作簿格式应在迁移完成后统一收敛，不长期维护两套互相不同的业务规则。
5. 导入按“选数据类型—填表/上传—核对—查看结果”组织。预检显示将新增或冲突的行、中文对象和分单位合计；提交成功显示实际入库条数，并可直接查看本批数据。
6. 首批明确采用“新记录导入；冲突记录不静默覆盖；已有记录在列表编辑”的简单规则。若后续确需批量更新，再增加显式更新操作；不把自动覆盖作为默认。
7. 后端优先利用已有导入批次和记录关联返回本批记录、实际数量和对象名称。是否已有可直接查询的批次关联需实施时确认；必要时补最小字段，不另建导入管理系统。

## 5. 沃衡演示包改进

保留现有两个生产基地。基于真实资料的对象名称习惯、表格结构、月度波动和设备关系，制作脱敏的沃衡场景；客户名称、联系方式和原始生产数值不直接发布到公开手册。

首批做四个完整案例：厂区购电、设备天然气、叉车柴油、空调制冷剂维护。电力和天然气优先，因为已有真实资料最清楚；柴油及制冷剂的活动细节需从相关原表/图片继续核对后再定。

每个案例同时提供：可下载的中文填报文件、手工新增用的一条样例、已导入的查询结果，以及对应能源/组织碳结果。示例明确归属工厂、车间、设备和月份。数据可适度缩放、脱敏，但各处使用同一套值，月度与年度汇总一致。

改变当前先造碳活动再反填能源的部分演示生成逻辑。能源类先准备原始输入，再调用现有能源写入和碳活动生成用例；制冷剂等非能源数据直接进入相应活动用例。demo ops 可调用服务，不必通过浏览器造全部数据，但必须与企业页面使用同一套校验和生成规则。

默认展示完成且可解释的案例；少量错误文件用于演示如何修改，不混入正常经营列表。测试创建的“手册验证”记录与客户演示案例分别管理，正式截图使用正常中文业务名称。

## 6. 分批实施与验收

| 批次 | 范围 | 验收标准 |
| --- | --- | --- |
| 第一批 | 购电、天然气案例；中文对象显示；能源新增/导入/查询/编辑/删除；导入结果页 | 用户从空的指定月份开始，导入后直接看到本批记录和正确合计；能改一条、删一条并看到变化；重复导入不会新增重复数据 |
| 第二批 | 能源生成组织碳活动，制冷剂及柴油分类操作 | 同一案例的能源量、生成活动量和核算结果对应；重复生成不增加重复活动；活动详情能辨认实际设备、物质与数量 |
| 第三批 | 从真实资料继续梳理运输、通勤及其他常用分类 | 每类有自己的必要字段和明确维护位置；不以一份电力表单截图替代全部分类 |
| 随各批完成 | 更新相应手册章节 | 同一案例连续展示填写表、保存/导入结果、详情、编辑前后、删除结果和查询汇总；一次讲清一个任务 |

第一批通过后再扩展，不先全量换图。最终讲解给工厂负责人看的核心结果是：这个月哪座工厂、哪个车间/设备用了多少能源，数据从哪里录入，哪里能改，怎样查看相应排放。

手册不再以页数和截图数作为完成标准。内部验收表逐项记录“入口—填写—保存—找到记录—编辑—删除—导入结果—查询汇总”的实际操作结果；尚未跑通的内容保留为未完成项。

## 7. 本轮维护与复测规则

- 正式手册源文件位于 `refine-lca/apps/docs/docs/energy-carbon/woheng/`，本仓库的旧静态 HTML 不作为新增正文的编辑源。
- 可下载填写样例由 `demo/ops/entry_samples.py` 和 `demo/samples/enterprise_entry/` 维护。中文能源导入 CSV 与页面下载模板共用同一字段规范；原始开发台账中的内部编号列不作为企业填报要求。
- 本地验证统一使用前端18101、后端18100。脚本以账号密码重新登录并确认当前租户，不依赖过期的 storageState；身份、接口失败、实际记录和值、截图加载状态分别检查。
- 演示包安装与浏览器写入验证必须串行。临时新增记录按本次运行保存的真实ID删除并回查，不按月份或设备批量清空。
- 能源维护脚本：`src/js/web/scripts/manual/verify-energy-data-maintenance.mjs`；组织碳维护脚本：`src/js/web/scripts/manual/verify-ghg-maintenance.mjs`。凭据通过现有 `E2E_ADMIN_EMAIL`、`E2E_ADMIN_PASSWORD` 环境变量传入，实际验收使用非superuser账号。变量名称不意味着必须使用系统管理员。
- 截图保持1440×900。长抽屉分上半页、下半页拍摄，不以缩放表单、裁掉保存按钮或只拍入口代替维护步骤。
- 手册中一张图只在对应章节展示一次。结构检查、截图审查清单和业务测试报告共同使用；图片存在或构建通过不能代替实际保存、删除和计算成功。
- 系统、迁移、沃衡演示数据和docs已同步发布。两基地普通账号业务验证及最终镜像只读浏览器回查均完成，证据按发布记录归档。
