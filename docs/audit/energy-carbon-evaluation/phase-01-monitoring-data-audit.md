# 第一阶段审查：综能监测与数据采集主线

## 审查范围

本阶段覆盖评价项 1-4、30-33，重点判断桌面端是否形成以下主线：

`项目/园区概览 -> 区域/设备接入配置 -> MQTT/电表点位映射 -> 实时读数与质量状态 -> 监测中心 -> 告警规则 -> 告警事件 -> 处理闭环 -> 来源追溯/导出`

整改原则：不为第一阶段新增旁路页面，不保留重复入口做兼容；优先重组现有 `/home`、`/data/company`、`/data/monitor-area`、`/data/terminals`、`/data/point-monitoring`、`/data/meter`、`/energy-carbon/monitor` 和 `/energy-carbon/alerts`。后端优先复用既有设备、测点、读数、告警、区域和租户模型，确需补充时只增加必要的校验、聚合或动作接口。

## 2026-09-01 第一轮整改记录

### 已实施

1. 设备入口收敛：客户侧侧边栏和平台入口不再暴露 `/data/device-types`、`/data/device-points` 两个重复设备入口，统一从 `/data/terminals` 进入“设备台账”。
2. 设备台账主线增强：在现有 `DeviceWorkbench` 内增加“设备接入主线”步骤条，并在设备详情中增加“接入”和“质量”两个 Tab。
3. 设备接入配置校验：复用现有设备、测点字段，前端校验采集协议、采集标识、启用测点、来源字段映射，并提供进入实时读数、监测中心、告警中心的动作。
4. 告警中心处理闭环：`/energy-carbon/alerts` 详情区增加处理说明、确认、转工单、关闭动作，移除跳转到事件台账处理的客户侧入口。
5. 预警规则业务表单：`/data/alarm-rules` 不再把 `设备ID`、`区域ID`、`阈值 JSON`、`来源表/视图` 暴露为主要业务字段；改为区域、设备、事件类型、等级、判断条件、阈值和单位，保存时仍写入既有 `range_val`。
6. 旧路由删除：`/data/device-types`、`/data/device-points`、`/data/alarm-events`、`/data/video-alarm-events` 四个客户侧独立路由已删除；访问旧路径会跳转回 `/home`，避免演示和手册继续依赖重复入口。

配置闭环实操验证见 `phase-01-configuration-validation.md`。

1. 设备台账已经能承载接入主线，但 MQTT 数据源、订阅 topic、网关状态和测试消息目前仍依赖既有字段组合与读数页面，没有形成后端级连接测试结果。

## 模块结论

### 1. 概览

| 项目 | 结论 |
| --- | --- |
| 对应路由 | `/home`, `/bigscreen/overview`, `/bigscreen/power`, `/bigscreen/carbon` |
| 当前状态 | 部分有效，已完成第一轮整改 |
| 有效点 | `/home` 已按能源运营 6 项、碳排放管理 6 项组织入口；有趋势和分区构成图，能作为工作台导航。 |
| 主要问题 | `/home` 的趋势和构成数据是前端静态数组，不是从当前租户的真实统计接口读取；它更像入口页，不是评价项所要求的项目/园区实时概览。 |
| 可用性影响 | 用户无法在首页判断当前租户数据是否真实更新，也无法从概览直接进入异常、设备、告警或待办处置。 |
| 改造建议 | 将现有 `/home` 改为租户级运营工作台：接入实时能耗、碳排、设备在线、未处理告警、数据质量、待办任务；每个指标可点击进入主流程页面。静态演示图从工作台移除，不作为业务功能证据。 |
