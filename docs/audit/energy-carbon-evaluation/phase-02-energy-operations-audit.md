# 第二阶段审查：能源运营与能效管理主线

## 审查范围

本阶段覆盖评价项 5-10，并交叉检查评价项 24、33 中与能源运营相关的内容。第二阶段拆成两个层次推进：

1. `P2A` 先审查能耗来源数据如何维护，包括自动计量、导入、人工台账、经营活动和强度分母。
2. `P2B` 再审查强度、分析、对标、能流、平衡、预算等结果页面是否闭环。

审查重点不是页面数量，而是桌面端是否形成以下业务主线：

`采集数据/人工台账 -> 能源消费事实 -> 能耗查询 -> 强度计算 -> 用能分析 -> 对标诊断 -> 能流/平衡测算 -> 预算目标与调整 -> 来源追溯/导出`

本轮先做代码级预审，确认路由、组件、接口和动作能力。数据来源维护已单独拆到 `phase-02a-energy-source-data-maintenance.md`，后续浏览器逐页实操应先完成 P2A，再进入 P2B 分析页面。

## P2A 数据维护地图

能源运营结果页依赖六类来源数据。各类数据需要分开审查，不能笼统写成“能耗数据已维护”。

| 数据类别 | 维护/查看页面 | 是否可维护 | 当前结论 |
| --- | --- | --- | --- |
| 区域、设备、测点、MQTT 映射 | `/data/monitor-area`, `/data/terminals` | 可维护 | P1 已完成基础闭环 |
| 自动计量读数 | `/data/point-monitoring`, `/data/meter` | 只读查看，来源于采集链路 | 部分有效 |
| 能源区间事实 | `/energy/consumption`, `/data/energy-consumption` | 可查询和导出；维护入口不清晰 | 部分有效 |
| 批量能源数据导入 | 后端 `/api/energy/imports/datasets` | 后端可导入；前端入口待补 | 待取证 |
| 温室气体活动数据 | `/carbon-mgmt/import`, `/carbon-mgmt/activities`, `/carbon-mgmt/category/$categoryCode` | 模板导入和查看；直接 CRUD 待取证 | 部分有效 |
| 作业量/产量/产值分母 | `/data/production-products`, `/data/production-output`, `/data/product-prices`, `/data/product-resource-bindings` | 可 CRUD | 部分有效 |
| 经营活动台账 | `/data/inbound`, `/data/outbound`, `/data/commute` | 入库/出库只读；通勤可 CRUD | 部分有效 |

P2A 详细审查见 `phase-02a-energy-source-data-maintenance.md`。在 P2A 未完成浏览器实测前，不应把后续强度、分析、预算页面判定为完整闭环。

## 页面级判断

### `/energy/consumption` 能耗查询

当前页面包含汇总查询、明细追溯、能源品种和导出记录四个页签，读取 `/api/energy/consumption/summary`、`/api/energy/consumption/facts`、`/api/energy/types` 和 `/api/energy/unit-conversions`，并提供 `/api/energy/consumption/export` CSV 导出。

当前结论：部分有效，接近可用。

有效点：

- 能从能源消费事实表查询能源品种、原始量、折标煤、区域、设施设备、状态和源记录。
- 支持周期、能源品种、Scope、状态、源记录类型、区域关键词等筛选。
- 已有导出接口，能作为能源消费明细证据。

问题：

- 明细追溯的“打开”动作只明确覆盖部分源记录类型，电表、经营活动、生产作业等来源跳转关系需要复核和补齐。
- `/data/energy-consumption` 是只读明细台账，与 `/energy/consumption` 功能重复，后续应合并为同一个能耗查询主入口或作为底层只读入口下沉。
- 当前还未做浏览器下载验证，导出文件是否带当前筛选条件、是否非空、是否字段完整仍待实测。

下一步：

1. 在浏览器中验证汇总、明细、能源品种、导出四个页签。
2. 检查导出 CSV 是否包含当前租户、当前筛选、非空数据。
3. 补齐源记录类型到电表读数、经营活动、人工台账、碳活动记录的业务跳转。

### `/energy/intensity` 能源消费量与强度

当前页面包含消费量汇总、面积强度、产品强度、产值强度、区域设备和趋势分析，读取 `/api/energy/intensity/*` 系列接口，并联动 `/api/production/products`。

当前结论：部分有效。

有效点：

- 能展示综合能耗、折标强度、面积强度、产品强度、产值强度和趋势。
- 后端查询已经区分能源品种、Scope、来源记录、产品、类别、产出类型、产线、区域和设备。
- 查询层有 GB/T 2589-2020 折标口径描述，具备标准追溯基础。

问题：

- 区域、设备、产线等筛选仍偏原始字段输入，不利于业务用户准确选择。
- 页面没有把强度计算拆成“分子能耗记录 + 分母面积/产量/产值记录 + 折标因子”的可追溯详情。
- 仓储场景中更应突出单位面积、单位作业量、单位订单/托盘/出入库量等强度，产品强度不是所有仓储演示的主线。

下一步：

1. 改为业务对象选择：基地、区域、设备、作业类型、产品/处理量。
2. 增加强度明细抽屉，展示分子、分母、单位、来源、状态和计算时间。
3. 浏览器验证面积强度、产品强度、产值强度在演示租户下均非空；仓储演示优先展示面积和作业量强度。

### `/energy/analysis` 能源消费分析与策略推荐

当前页面包含结构分析、成本分析、能效分析、异常诊断、策略建议，读取 `/api/energy/analysis/summary`、`/api/energy/analysis/anomalies` 和 `/api/energy/analysis/strategies`。

当前结论：部分有效。

有效点：

- 具备能源结构、费用结构、设备能效排行、异常点和策略建议展示。
- 查询支持周期、粒度、能源品种、区域、设备、用能系统和分时电价。

问题：

- 异常诊断没有形成“确认异常、查看原始记录、转告警/工单/整改、复核效果”的处理链路。
- 策略建议目前是文本和指标展示，不能直接生成减排措施、预算调整、设备运维任务或能效改进记录。
- 成本和能效分析缺少下钻到对象详情，用户难以定位具体设备、区域或点位。

下一步：

1. 保留现有统计接口，前端补“异常详情”抽屉和来源跳转。
2. 策略建议增加“生成整改措施/转预算调整”动作，优先复用现有减排项目、预算调整或工单能力。
3. 浏览器验证异常列表、策略建议是否存在有效数据；无数据则补演示样本。

### `/energy/benchmark` 能效对标

当前页面包含历史基线、行业标杆库、设备/工序对标、对标结论和整改建议，读取并写入 `/api/energy/benchmark/*`。

当前结论：部分有效。

有效点：

- 能新增标杆方案、标杆项，支持删除标杆项。
- 能基于历史数据生成最优基线、P25、均值方案。
- 有对标结果、偏差、节能潜力、缺失标杆和整改建议展示。

问题：

- 后端有更新接口，但前端当前只看到新增和删除，编辑动作需要补齐或浏览器确认。
- 标杆对象以 `target_code`、`target_name` 手工输入为主，没有与设备、区域、用能系统、产品等实际对象选择打通。
- 整改建议没有进入整改任务、减排项目或预算调整流程。

下一步：

1. 标杆方案和标杆项补编辑动作，避免“新增后不能修正”。
2. 对标对象改成对象选择器，编码自动带出。
3. 对标结果支持一键进入能源分析、平衡优化、整改措施，保留来源和置信度字段。

### `/energy/flow` 能流分析

当前页面包含能流图、能量平衡表、损耗诊断和分析报告，读取 `/api/energy/flow/graph`、`/balance`、`/losses`、`/report`。

当前结论：部分有效。

有效点：

- 能以图、表、损耗列表和报告形式展示能源输入、输出和损耗。
- 筛选支持周期、粒度、能源品种、区域、用能系统和损耗阈值。

问题：

- 能流拓扑和节点关系目前没有清晰配置入口，用户难以维护“外购电力 -> 配电室 -> 分区/设备 -> 作业系统”的关系。
- 损耗阈值是页面临时筛选值，不像可审计的规则配置。
- 分析报告是展示结果，没有导出、保存、纳入报告或转整改动作。

下一步：

1. 不新增独立拓扑实体，优先复用区域、设备、能源品种、用能系统字段形成可维护映射。
2. 损耗阈值纳入已有规则/参数配置，并在页面显示来源。
3. 报告页签补导出或保存动作，至少能生成可引用的分析记录。

### `/energy/balance` 能效平衡与优化

当前页面包含平衡简表、数据质量、优化测算和优化记录，读取 `/api/energy/balance/*`，并通过 `/api/energy/balance/simulate`、`/api/energy/balance/records` 写入测算与记录。

当前结论：部分有效，核心测算链路具备闭环基础。

有效点：

- 能展示平衡概要、输入输出、损耗、数据质量和优化场景。
- 能发起优化模拟，并保存优化记录。
- 页面和后端已具备“测算结果 -> 记录留存”的主线。

问题：

- 平衡对象仍以对象类型和编码过滤，业务用户需要更自然的区域/设备/用能系统选择。
- 优化记录缺少编辑、状态流转、效果复核。
- 优化参数需要明确来源和口径，避免形成难以解释的自由假设。

下一步：

1. 优化测算表单引入对象选择、场景选择和参数来源字段。
2. 优化记录补状态、责任人、实施周期和效果复核入口，优先复用整改/减排措施能力。
3. 浏览器验证模拟、保存、记录回读和数据质量页签。

### `/energy/budget` 能碳预算

当前页面包含年度目标、月度预算、执行偏差、预测超限和调整审批，读取并写入 `/api/energy/budget/*`。

当前结论：部分有效。

有效点：

- 能新增年度预算目标。
- 能生成月度预算。
- 能查看执行率、偏差、超限预警、预测结果和规则建议。
- 能新增预算调整记录。

问题：

- 预算目标前端当前只看到新增，后端虽支持更新/删除，但页面缺少对应编辑、停用、删除动作。
- 调整审批页面允许直接选择草稿、提交、批准状态，不符合正式审批的操作路径。
- 预算目标对象仍是编码和名称手填，缺少基地、区域、设备对象选择。
- 规则建议没有形成整改任务、预算调整或责任人跟踪。

下一步：

1. 补预算目标编辑、停用/启用、删除动作。
2. 调整审批拆成申请、提交、批准/驳回的按钮流转，状态由动作产生。
3. 目标对象改为业务选择器；规则建议可生成预算调整或整改措施。
4. 浏览器验证新增目标、生成月度预算、新增调整、调整回读。

## 分析页维护职责混入诊断

本轮只检查能源分析类页面是否承担了本应在具体业务维护页面完成的 CRUD 或配置职责；分母数据、经营活动和碳核算数据不纳入本次处理。

结论：能源分析类页面中有 3 个页面存在明确的维护/配置职责混入，合计 8 类动作或页签需要后续迁移、合并或重新定性。另有 2 个页面存在“分析结果留存/测算操作”，可先保留为分析闭环动作，不按主数据维护问题处理。

| 页面 | 混入内容 | 数量 | 处理判断 |
| --- | --- | ---: | --- |
| `/energy/consumption` | 能源品种、单位换算在能耗查询页面内展示维护口径；能源数据维护此前也散落为只读入口 | 2 | 本轮已新增 `/data/energy-types`、`/data/energy-unit-conversions`、`/data/energy-consumption` 主入口；后续 `/energy/consumption` 只保留查询、分析、追溯、导出和跳转按钮 |
| `/energy/benchmark` | 标杆方案新增、标杆项维护、历史数据生成标杆方案 | 3 | 标杆库本质是配置/参考数据维护，应迁到独立维护入口或改成该模块的“标杆库维护”工作台；对标分析页只保留方案选择、结果、差距和整改入口 |
| `/energy/budget` | 年度预算目标新增、月度预算生成、预算调整新增/状态维护 | 3 | 预算是管理业务，不是单纯分析页；应从“能源分析”中重新定性为“能碳预算管理”，补编辑、停用、删除和动作式状态流转 |
| `/energy/flow` | 损耗阈值筛选、分析报告展示 | 0 | 当前没有主数据 CRUD；后续补阈值来源和报告导出即可 |
| `/energy/balance` | 优化测算、保存优化记录 | 0 | 属于计算结果闭环，可保留在分析/优化页；后续只补对象选择、状态和效果复核 |
| `/energy/intensity` | 强度展示、趋势、排行 | 0 | 当前未发现主数据维护混入；后续重点是分子/分母来源解释和对象选择 |
| `/energy/analysis` | 结构、成本、异常、策略展示 | 0 | 当前未发现主数据维护混入；后续重点是异常下钻和转处置 |

后续改造原则：

1. 能源主数据只在 `/data/energy-types`、`/data/energy-unit-conversions` 维护。
2. 能源事实只在 `/data/energy-consumption` 维护，分析页最多提供跳转入口。
3. 对标库若继续提供维护能力，应作为“能效对标”的配置工作台，不再混在结果页主体中。
4. 能碳预算应按管理页面处理，不纳入普通能源分析页面。
5. 分析页保留筛选、图表、结果、明细下钻、导出和跳转，不承担基础台账 CRUD。

## 阶段整改建议

按不做后向兼容、不做旁路逻辑、不必要不增实体的原则，第二阶段建议这样推进：

| 优先级 | 模块 | 整改任务 | 实现方式 | 验收方式 |
| --- | --- | --- | --- | --- |
| P2A-1 | 来源准备度 | 先确认当前租户有哪些能源、活动和分母数据 | 复用 `/api/energy/source-readiness`，必要时在能源工作台展示 | 当前租户能源区间事实、Scope 1/2 活动、产量/作业量分母均非空 |
| P2A-2 | 自动计量来源 | 验证设备、测点、MQTT 映射到读数和能源事实 | 复用 `/data/terminals`, `/data/point-monitoring`, `/data/meter` | 设备测点配置、最新读数、电量汇总和来源追溯一致 |
| P2A-3 | 非电表导入 | 补清楚能源区间事实和作业量事实导入入口 | 复用现有导入接口和导入组件，不新增旁路数据模型 | 导入后能在 `/energy/consumption` 或 `/data/production-output` 回读 |
| P2-1 | 能耗查询 | 统一明细和追溯入口，补源记录跳转和导出验证 | 复用现有能源消费事实接口；合并 `/data/energy-consumption` 到 `/energy/consumption` 主流程 | 浏览器下载 CSV，检查非空、筛选一致、字段完整 |
| P2-2 | 强度计算 | 强度结果可解释、可下钻 | 复用现有强度接口，前端增加对象选择和计算明细抽屉 | 面积/作业量/产品/产值强度均能展示来源记录 |
| P2-3 | 用能分析 | 异常和策略可处置 | 复用告警、工单、预算调整或减排措施，不新增独立策略任务实体 | 从异常列表进入详情，并生成一条可回读处置记录 |
| P2-4 | 能效对标 | 标杆对象与实际业务对象打通 | 复用设备、区域、用能系统、产品选择器；补编辑动作 | 新增、编辑、删除、历史生成、对标结果均可回读 |
| P2-5 | 能流分析 | 能流关系可维护、损耗规则可追溯 | 复用区域、设备、能源品种和用能系统字段；阈值来源纳入现有规则/参数 | 能流图节点非空，损耗阈值有来源，报告可导出或保存 |
| P2-6 | 能效平衡 | 优化测算结果进入实施跟踪 | 复用优化记录和整改/减排措施能力，补状态和责任字段 | 模拟、保存、回读、复核入口可操作 |
| P2-7 | 能碳预算 | 预算目标和调整审批形成闭环 | 使用既有预算计划、分解、调整接口；前端补编辑和动作式审批 | 新增目标、生成月度、申请调整、提交、批准/驳回均可验证 |

## 当前判断

第二阶段已有较多后端接口和部分写入动作，不属于“只有静态页面”。但从前端业务可用性看，当前主要短板是对象选择、来源追溯、分析结果处置、审批/状态流转和导出验证。后续整改应优先让现有页面闭环，合并重复只读入口，不新增平行页面。
