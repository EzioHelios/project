# 能碳平台页面审查与整改进度台账

本台账作为能碳平台实质功能审查的唯一进度记录。每次页面审查、页面整改、浏览器验证、截图补拍和手册更新完成后，都在本文件更新状态，避免重复审查、重复截图和重复改造。

## 使用规则

1. 一个业务页面只保留一个主记录。页面拆分、合并或删除时，在原记录中说明去向，不再新建平行记录。
2. 每个记录同时跟踪五类状态：审查、整改、验证、截图、手册。
3. 状态不以页面存在为准，而以业务链路是否可操作、可配置、可编辑、可展示、可追溯为准。
4. 已标为“已闭环”的页面，后续除非业务范围变化、路由重构或验证失败，不再重复做第一轮审查。
5. “部分有效”和“待验证”必须写明下一步动作；不得只写笼统描述。
6. 页面合并优先于兼容旧入口。旧路由删除或迁移后，在“去向”列记录主入口。

## 状态口径

| 状态 | 含义 |
| --- | --- |
| 未开始 | 尚未做代码、页面和浏览器实测。 |
| 已审查 | 已阅读路由、组件、接口和页面，形成问题判断。 |
| 已整改 | 已完成必要的页面、接口、数据或权限改造。 |
| 已验证 | 已通过接口或浏览器验证关键业务动作。 |
| 已入册 | 已补充到操作手册或演示材料。 |
| 部分有效 | 有页面或数据，但关键动作、状态流转、追溯或角色权限不完整。 |
| 待验证 | 已有实现，但还缺浏览器实操或接口回读证据。 |
| 已合并 | 原入口不再作为主页面，功能并入新的主入口。 |
| 不适用 | 当前产品范围暂不承接。 |

## 不重复工作控制

后续开始某一模块前，先执行以下检查：

1. 在本文件查该路由是否已有“已闭环”记录。
2. 在 `requirements-matrix.md` 查该页面对应的评价项，确认是否属于当前阶段。
3. 在 `manual-manifest.json` 和 `manual-audit.json` 查是否已有截图和手册入口。
4. 在截图脚本中查是否已有证据 ID，优先补强现有证据，不新增重复证据。
5. 如果页面已合并，后续只改主入口，不恢复旧入口。
