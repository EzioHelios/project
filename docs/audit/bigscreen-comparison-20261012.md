# 祥泰原版与现版大屏逐页、逐组件对比

审查日期：2026-10-12。性质：现状审查与复刻清单，不是已完成改造的验收报告。

## 1. 结论

客户反馈有依据。现版并非原版的完整迁移：它保留了大屏边框、三维背景和部分专用图示，却将“仓库现场运行”内容改成了以月度购电和组织核算为主的统计展示。增加页面数量没有补回视频安全、用发电协同、储能、区域碳排等内容。

主要问题按优先级排列：

1. **业务内容迁移不完整**：总览缺少仓库档案、发电/用电终端状态、预警分布、视频概况；电能页缺少仓库/光伏/充电桩切换与储能；碳页缺少原有运行碳排、光伏减排、区域排行、强度趋势。
2. **数据链换了，但页面没有说明其业务范围变化**：现版总览/电量读电表月度聚合，碳页读组织碳核算批次。原版读日/周/月/年运行视图、光伏与充电设备、通勤和出入库金额。不是将旧数据再导入一次就能恢复原版。
3. **当前真实缺口**：祥泰能耗有值而组织碳结果为空；摄像头有列表但抽查通道无播放配置；介绍页有破图，并显示开发阶段文案。
4. **信息密度和可读性下降**：大块竖向 KPI、静态“当前视图摘要”、空“协同说明”占位置；底部曲线很小；排行坐标轴文字叠在一起；卡片内容被下边界截断。
5. **可复用但不能直接搬用另一演示页的数据**：光伏、充电桩、储能等组件已存在，主要用于 `huayi` 页；其后端服务返回固定示例数值，不是安方/祥泰数据。

建议先恢复原版四个业务主题的内容契约和布局，再补数据接入。保留现有租户隔离、真实模型、规范组织核算；不要重新引入旧 Django 旁路或把华谊示例数据当客户数据。

## 9. 新增页和视觉问题

### 企业介绍

逐项查看：企业图集、企业信息摘要、品牌叙事、运营视角、运营项目轮播、成功案例轮播。

- 企业档案有真实字段：祥泰员工41人、仓储10,200m²、园区25,600m²；这是“已有数据未在总览有效利用”，不是全库无资料。
- 项目轮播由前三个区域生成，成功案例由第5–8张区域照片生成，并无独立项目/案例业务来源。设备照片被命名为成功案例，语义不成立。
- 实际截图出现破图；另有区域无图显示“暂无图片”。需分别处理失效链接和确无图片，不能用示意图伪装实拍。
- 浏览器真实显示“首版介绍页优先复用现有主数据……后续可继续替换为客户定制内容”。来源 `_bigscreen.py:162–167`，必须清理。
- 企业信息纵向卡片和底部品牌叙事被固定面板裁切。不是把文字补更多就能解决，应改紧凑字段布局。

### 园区模型

- 祥泰模型、卫星底图、俯视按钮实际可用；安方切换后模型发生变化，保留这些成果。
- 不将模型本身重做当成首要任务。优先补“区域/设备/摄像头点位与真实记录”的业务关联。
- 介绍页仓库位置文本和模型地址文本不同，需与客户档案核对，不能凭此次观察断言哪个地址正确。

### 共同UI缺陷

1. 1920画布下区域/电表排行横轴每个刻度重复`kWh`，数字重叠；单位应独立显示，刻度缩写与数量受控。
2. 底部面板窄而数据标签长，Sankey文字被右边缘截断；需要留标签空间或精简节点，不是增加动效。
3. 明亮卫星图透过半透明面板，图表轴与次级文字对比不足。
4. 碳饼图的零值标签/图例拥挤；只有一个实际Scope时不应为三个重复图占满屏幕。
5. 电力因子趋势只有一个点，组件又`showSymbol: false`，因此看起来像空图；不仅是ECharts没等加载。
6. 现版时钟是10月，展示账期8月、预警6月或去年12月；应明确数据时间范围，不让动效造成实时误解。

## 11. 旧实现不能原样复制的地方

- 原后端固定 `YD_CPFL_PFYZ = GF_CJPL_PFYZ = 0.5810`；没有按年度/地区/版本选择。
- “净排放”直接用用电排放减去光伏估算减排，注释假设光伏全部上网、没有储能。与现有仓库事实和组织核算不必然同义。
- 通勤使用固定0.75修正，以及周5/月22/年250天；需要明确企业假设或真实记录，不暗置计算。
- “碳资产收益”使用`abs(jcpfl * 50 / 10000)`，没有资产交易/确权数据，还涉及量纲核对。不能为了复刻恢复成真实资产金额。
- 旧运行接口以服务器“今天”为期间基点，不可直接用于多年历史演示；现版应可选择实际有数据的期间。
- 原视频播放有localhost WebRTC地址/演示视频分支；旧天气按时段切图；这些都不等于现场能力。
- 旧匿名接口及“一键处理全部事件”不能照搬为客户写权限。

本轮仅记录代码事实，不确定新的计算公式。实施涉及排放/减排/强度时，需按仓库已确认边界和仓库标准资料记录来源后实现。
