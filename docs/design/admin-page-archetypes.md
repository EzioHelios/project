# 工业能碳后台页面 Archetypes 规范

调研日期：2026-06-13  
适用项目：工业能碳后台，React / Tailwind / shadcn 技术栈

## 0. 目的

本规范用于解决当前后台“功能堆叠”的问题。每个页面在进入视觉设计前，必须先归入一个页面 archetype。页面类型确定后，布局、密度、筛选、操作、空状态、错误状态、图表和详情结构都应服从模板，而不是每页重新发明一只小轮子。

本项目后台建议采用 6 类核心页面：

1. Workbench 工作台
2. Ledger 台账
3. Analysis 分析
4. Audit 审核
5. Reference Data 主数据
6. Settings 配置

详情页作为横跨多类页面的 Object Detail 模板存在，不单独作为一级 archetype。

## 1. 全局后台骨架

所有后台页面应共享以下外壳：

### 1.1 Admin Shell

- 左侧导航：按业务域组织，避免把所有数据表直接暴露为菜单。
- 顶部栏：租户 / 企业、当前组织、用户、通知、帮助。
- 内容区：统一宽度策略，常规页面使用全宽但有内边距，详情页可采用最大宽度或左右分栏。
- 全局状态：加载、无权限、接口失败、维护中、数据过期。

### 1.2 Page Header

页面顶部必须说明：

- 页面标题
- 页面类型或对象类型
- 业务说明，不超过一行
- 主操作按钮
- 次级操作入口
- 当前对象或数据集状态

不建议在 header 放大段说明文案。后台不是展厅，用户不需要每页读一篇序言。

### 1.3 Context Bar

Context Bar 是本项目避免“每页自由拼 UI”的关键。以下字段按页面需要出现：

- 核算周期 / 时间范围
- 组织边界 / 企业 / 园区 / 车间
- Scope / 排放类别
- 能源介质
- 区域 / 设备 / 测点
- 数据来源
- 数据质量
- 审核状态

Context Bar 分两层：

- 主筛选：3 到 6 个最高频条件，始终展开。
- 高级筛选：低频字段进入抽屉或折叠区。

### 1.4 Data Source 与 Audit Footer

凡是展示计算结果、指标、图表的页面，都应显示：

- 数据更新时间
- 数据来源
- 统计口径
- 单位
- 是否包含估算数据
- 审核或锁定状态

详情页底部或侧栏应展示审计信息：创建人、创建时间、更新人、更新时间、提交人、审核人、版本、变更记录。

## 2. Workbench 工作台

### 2.1 使用场景

工作台用于回答：“今天我需要处理什么？”不是用来展示所有指标，也不是领导驾驶舱。

适用对象：

- 待补录活动数据
- 待审核核算批次
- 数据质量异常
- 因子到期 / 失效
- 缺少证据附件
- 超预算或能耗异常
- 未完成任务

### 2.2 页面结构

1. Page Header：工作台标题、当前组织、周期切换。
2. KPI Strip：只放待处理数量、异常数量、核算完成率、审核通过率等任务型指标。
3. Task Queue：按优先级展示任务，支持筛选“我的 / 全部 / 逾期”。
4. Exception Panel：数据缺失、异常波动、因子匹配失败。
5. Quick Actions：导入活动数据、发起核算、创建审核、维护因子。
6. Recent Activity：最近提交、审核、驳回、导入记录。

### 2.3 组件清单

- `AdminPageHeader`
- `ContextBar`
- `MetricStrip`
- `TaskQueue`
- `ExceptionList`
- `StatusBadge`
- `AuditTimelineMini`

### 2.4 反模式

- 不要做全屏大屏背景。
- 不要放 12 个 KPI 卡片。
- 不要用大段欢迎文案填空间。
- 不要把所有菜单入口都放成图标宫格。

## 3. Ledger 台账

### 3.1 使用场景

台账是后台最常见的页面。它不是数据库表可视化，而是“可筛选、可操作、可审计的业务对象列表”。

适用对象：

- 企业档案
- 监测区域
- 设备与测点
- 能耗数据
- 活动数据
- 排放源
- 排放因子
- 计算因子
- 核算批次
- 核查证据
- 预算记录

### 3.2 页面结构

1. Page Header：对象名称、数量、主操作。
2. Context Bar：周期、组织、Scope、状态等。
3. Table Toolbar：搜索、列配置、导入、导出、批量操作。
4. Data Table：高密度表格，固定关键列，数值右对齐，状态列固定位置。
5. Row Action：查看、编辑、复制、停用 / 归档，危险操作进入更多菜单。
6. Detail Drawer：快速查看详情，不打断列表上下文。
7. Empty / Error / Permission State：不同原因对应不同动作。

### 3.3 表格列标准

台账表格建议按以下顺序组织列：

1. 标识列：名称 / 编码 / 对象 ID
2. 业务上下文：组织、区域、Scope、类别、周期
3. 核心数值：活动数据、能耗、排放量、预算值等
4. 计算相关：因子、公式、数据来源、质量等级
5. 状态列：草稿、待审核、已通过、已驳回、已锁定、已停用
6. 审计列：更新人、更新时间、提交人、审核人
7. 操作列

### 3.4 反模式

- 每页重新设计筛选区。
- 表格列无顺序，状态列位置飘来飘去。
- 行操作全部铺开，导致每行像工具箱。
- 单元格里重复显示单位，导致表格噪音过大。单位应优先放在列标题。
- 把导入、导出、批量删除、编辑、审核都做成同级按钮。

## 4. Analysis 分析

### 4.1 使用场景

分析页用于回答：“数据发生了什么，为什么，下一步查哪里？”它不负责大量录入，也不负责审批，但要能钻取到台账和详情。

适用对象：

- 能流分析
- 能耗趋势
- 碳排趋势
- 能效对标
- 碳排热点
- 预算偏差
- 峰谷平分析
- 异常分析

### 4.2 页面结构

1. Page Header：分析主题、口径说明、保存视图。
2. Context Bar：组织、时间范围、能源介质、区域、设备、数据粒度。
3. KPI Strip：3 到 6 个关键指标，带单位、同比 / 环比、更新时间。
4. Chart Grid：2 到 6 个图表面板，每个 panel 有标题、口径、单位、tooltip、空状态。
5. Breakdown Table：图表下方保留明细表或异常列表。
6. Drilldown Drawer：点选图表或表格行后，展示相关设备、测点、活动数据、原始记录。

### 4.3 图表面板规范

每个图表 panel 必须声明：

- 指标名称
- 单位
- 时间粒度
- 数据范围
- 数据来源
- 更新时间
- 是否包含估算值
- 空状态原因
- 点击后的钻取路径

### 4.4 推荐图表白名单

- 趋势：折线图 / 面积图
- 对比：柱状图 / 分组柱状图
- 构成：堆叠柱 / 条形图，谨慎使用饼图
- 热点：Top List / Pareto
- 时间分布：热力格 / 日历热图
- 设备 / 区域：树表 + 图表，不建议直接上复杂 3D
- 异常：趋势 + 事件 overlay + 异常明细表

### 4.5 反模式

- 图表没有单位。
- KPI 没有时间范围。
- 用环形图填空间。
- 为了高级感增加发光地图、粒子背景和 3D 管线。
- 图表无法跳到原始数据。

## 5. Audit 审核

### 5.1 使用场景

审核页用于回答：“这批数据是否可信，依据是什么，谁做过什么？”

适用对象：

- 核算批次
- 审核记录
- 核查证据
- 因子变更审批
- 数据补录审批
- 计算结果锁定
- 报告生成和归档

### 5.2 页面结构

1. Page Header：审核对象、批次编号、状态、主操作。
2. Status Flow：草稿、已提交、校验中、待审核、已通过、已驳回、已锁定。
3. Summary Strip：排放总量、活动数据完整率、因子匹配率、异常数、证据缺失数。
4. Validation List：缺失、异常、估算、因子过期、证据不足。
5. Evidence Panel：附件、来源、上传人、关联字段、预览。
6. Calculation Trace：活动数据 × 因子 × GWP / 单位转换 = 结果。
7. Audit Timeline：提交、退回、备注、修改、通过、锁定。
8. Action Bar：通过、驳回、要求补充、重新计算、锁定、导出审计包。

### 5.3 审核状态语义

- `draft` 草稿：可编辑，未进入审核链。
- `submitted` 已提交：业务人员完成提交，等待校验或审核。
- `validating` 校验中：系统规则检查中。
- `needs_fix` 待补正：发现缺失或错误，需要责任人处理。
- `reviewing` 审核中：审核人处理中。
- `approved` 已通过：可进入报告或锁定。
- `rejected` 已驳回：需说明原因，保留驳回记录。
- `locked` 已锁定：不可编辑，只能走解锁流程。

### 5.4 反模式

- 只用一个“通过 / 不通过”按钮。
- 驳回原因放在普通备注里，无法结构化。
- 计算结果没有追踪公式和因子版本。
- 证据附件和活动数据分离，审核人来回跳页。

## 6. Reference Data 主数据

### 6.1 使用场景

主数据页面用于管理稳定但影响全局的数据。主数据错误会像坏齿轮一样污染所有后续计算，因此页面应强调版本、适用范围、停用策略和变更记录。

适用对象：

- 企业档案
- 组织边界
- 监测区域
- 设备与测点
- 排放源分类
- 排放因子
- 计算因子
- 单位字典
- 标准来源

### 6.2 页面结构

1. Page Header：对象类型、主操作。
2. Search + Filter：关键字、状态、适用范围、版本、来源。
3. Master List：表格或树表。
4. Detail Panel：基本信息、适用范围、版本、关联对象、变更记录。
5. Version Control：生效日期、失效日期、替代关系。
6. Impact Preview：修改后影响哪些核算批次、报告、设备或公式。

### 6.3 排放因子页特殊规则

排放因子详情必须包含：

- 因子名称
- 因子编码
- 因子值
- 单位
- 适用地区
- 适用时间
- Scope / 类别
- 来源机构
- 来源文件或标准
- 版本号
- 生效 / 失效时间
- 是否默认
- 是否供应商特定
- 是否自定义
- 关联公式
- 变更记录

### 6.4 反模式

- 直接编辑因子值但不保留版本。
- 因子停用后影响历史结果。
- 主数据详情页没有“被哪些对象引用”。
- 使用字典配置模拟严肃的标准数据管理。

## 7. Settings 配置

### 7.1 使用场景

配置页用于低频但高影响的系统行为设置。它和主数据的区别是：主数据是业务对象，配置是系统规则。

适用对象：

- 权限角色
- 字典项
- 计算公式模板
- 导入模板
- 数据校验规则
- 审批流配置
- 告警阈值
- 通知规则
- 报告模板
- 第三方集成

### 7.2 页面结构

1. Settings Shell：左侧设置分组，右侧配置内容。
2. Configuration Section：标题、说明、字段组。
3. Risk Notice：高影响设置需要风险提示。
4. Preview / Test：公式、接口、模板应支持预览或测试。
5. Change Log：配置变更记录。
6. Publish / Rollback：重要配置应有发布和回滚。

### 7.3 反模式

- 把所有配置放进一个巨型表单。
- 配置修改立即生效但没有提示影响范围。
- 公式配置自由输入，没有测试、版本和权限。
- 导入模板配置无法与实际字段映射联动。

## 8. Object Detail 详情页模板

详情页不是孤岛，它应服务台账、审核和主数据。

### 8.1 详情页结构

1. Object Header：名称、编码、状态、主操作。
2. Key Facts：组织、周期、Scope、数值、单位、数据来源。
3. Tabs：基础信息、数据明细、因子 / 公式、证据、审核、变更记录。
4. Right Rail：状态流、责任人、最近操作、风险提示。
5. Footer：创建和更新信息。

### 8.2 详情页类型

- Compact Detail Drawer：用于列表快速查看，不承载完整编辑。
- Full Object Page：用于复杂对象，例如核算批次、设备、因子。
- Audit Detail：用于审核对象，突出证据和状态流。
- Analysis Drilldown：从图表进入，突出上下文和相关明细。

| 业务对象 | 主 archetype | 辅助 archetype | 说明 |
| --- | --- | --- | --- |
| 企业档案 | Reference Data | Detail | 企业级组织边界和基础资料，重版本和变更记录 |
| 监测区域 | Reference Data | Ledger | 适合树表 + 详情，关联设备与测点 |
| 设备与测点 | Reference Data | Ledger / Detail | 需要状态、数据源、计量单位、归属区域 |
| 能耗数据 | Ledger | Analysis | 台账负责录入和校验，分析页负责趋势和异常 |
| 活动数据 | Ledger | Audit / Import | 需要导入、字段映射、因子匹配、证据 |
| 排放因子 | Reference Data | Audit | 重来源、版本、适用范围、影响分析 |
| 计算因子 | Reference Data | Settings | 与公式模板和标准口径关联 |
| 核算批次 | Audit | Ledger / Detail | 是碳核算核心对象，必须有状态流 |
| 审核记录 | Audit | Detail | 与批次、活动数据、证据关联 |
| 核查证据 | Audit | Ledger | 可作为附件台账，也可嵌入审核页 |

| 能效对标 | Analysis | Ledger | 需要对标对象、基准、偏差、改进建议 |
| 预算管理 | Ledger | Analysis / Audit | 预算台账 + 偏差分析 + 调整审批 |

## 10. 页面命名和路由建议

建议路由命名与 archetype 对齐：

- `/dashboard/workbench`：任务工作台
- `/carbon/accounting`：核算批次审核型页面
- `/carbon/activity-data`：活动数据台账
- `/carbon/emission-factors`：排放因子主数据
- `/carbon/evidence`：核查证据台账
- `/energy/analysis`：能源分析页
- `/energy/consumption`：能耗数据台账
- `/energy/assets`：设备与测点主数据
- `/settings/calculation`：计算规则配置
- `/settings/import-templates`：导入模板配置

## 11. 试点页面归类

### 11.1 `/carbon/accounting`

建议 archetype：Audit + Ledger + Detail

原因：碳核算不是单纯分析页。它应以核算批次为核心，串联活动数据、因子匹配、计算结果、证据、审核和锁定。

推荐结构：

- Header：核算批次、周期、组织、状态。
- Context Bar：企业 / 组织、周期、Scope、边界、口径。
- Summary Strip：排放总量、活动数据完整率、因子匹配率、异常数、证据缺失数。
- Tabs：活动数据、因子匹配、计算结果、异常校验、证据、审核日志。
- Right Rail：状态流、当前处理人、下一步动作。

### 11.2 `/energy/analysis`

建议 archetype：Analysis + Drilldown Detail

原因：能源分析属于数据分析页，应借鉴 Grafana / Datadog 的 panel grid，但必须保留工业能源语义。

推荐结构：

- Header：能源分析、保存视图、导出。
- Context Bar：时间、组织、区域、能源介质、设备、粒度。
- KPI Strip：总能耗、单位产值能耗、峰谷比、同比、异常点数。
- Chart Grid：趋势、分项构成、峰谷平、区域 / 设备 Top、异常事件。
- Bottom Table：异常明细或测点明细。
- Drilldown Drawer：原始数据、设备信息、关联事件、处理建议。

## 12. 验收清单

新页面进入开发前必须回答：

- 这个页面属于哪个 archetype？
- 主对象是什么？
- 用户的主要任务是什么？
- 需要哪些上下文筛选？
- 是否需要 KPI strip？
- 主操作和危险操作分别是什么？
- 状态有哪些？是否复用全局状态体系？
- 是否需要审计字段？
- 空状态、错误状态、无权限状态是什么？
- 是否能从汇总钻取到明细？
- 是否有数据来源、单位、更新时间和口径说明？
